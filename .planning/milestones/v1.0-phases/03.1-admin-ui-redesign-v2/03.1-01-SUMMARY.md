## Decisions Made

1. **bUnit lives in `Directory.Packages.props` as a TEST-only pin** — CLAUDE.md "no new NuGet packages" interpreted as a runtime-distributable constraint; bUnit ships exclusively inside `tests/*` projects (which carry `<IsPackable>false</IsPackable>`). The CPM pin block carries an inline comment documenting this interpretation so future plan authors do not re-litigate.
2. **5 of 6 stubs `using Bunit;` even though the body is empty** — the import-only line locks the bUnit reference into the compilation graph. If a later plan accidentally drops the bUnit `<PackageReference>`, those 5 files fail to compile rather than silently regressing.
3. **`AuditSentenceProjectorTests` deliberately xUnit-only** — the projector is a static function over `(action, actor, target, before, after, reason)`; testing it via bUnit's `TestContext` would be ceremony without value. Mirrors the existing `PlayerSearchInputDetectionTests` table-driven xUnit precedent (PATTERNS.md PA-AuditSentenceProjectorTests).
4. **Bundle category lives in its own `Bundle/` subdirectory** — separate from `Components/` so `--filter Category=Bundle` and `--filter Category=Component` are non-overlapping. A future asset-size test (e.g. JS bundle) drops into the same directory.
5. **`CssBundleSizeTests` live from day one** — every later plan that touches `gamekit-admin.css` (notably plan 03.1-02 sketch port, plans 03.1-04/05/06 component CSS) gets immediate feedback if the payload escapes budget. Anchoring it to a skipped placeholder would defer a test that already passes — net negative.
6. **Budget = 27 941 B (not 26 624 B as PATTERNS.md PA-CssBundleSizeTests scratched out)** — uses RESEARCH §Performance Budgets value of 1 339 B baseline + 25 × 1 024 B + 8-byte header variance per the executable plan spec.
