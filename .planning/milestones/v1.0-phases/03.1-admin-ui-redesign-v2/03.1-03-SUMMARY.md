# Phase 03.1 Plan 03: JS interactivity bundle + JS↔Blazor bridge — Summary

**One-liner:** Vanilla JS IIFE (`window.GKAdmin`) owns Cmd+K palette + Tweaks read/write/apply + sidebar toggle + clipboard + audit row expand + verb-engine palette interactivity (filter / arrow-cycle / Enter / two-step target search via `/admin/api/players/search`); MainLayout exposes `[JSInvokable] OpenDialog` over a `DotNetObjectReference` bridge so the palette can launch the Phase 03 dialogs without round-tripping keystrokes through SignalR.

## What landed

### `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js` (NEW — 393 lines / 15 555 bytes)

Single IIFE; one global (`window.GKAdmin`); no module boundaries; `'use strict'`. Sections:

- **Tweaks I/O** — `loadTweaks` / `saveTweaks` / `resetTweaks` / `applyAttrs` against `localStorage 'gamekit.admin.tweaks'`, with five `[data-*]` attribute keys (`accent`, `density`, `sidebar`, `banLoud`, `dashDir`) mapped to their HTML attribute names.
- **Palette / Tweaks open/close** — `openPalette` / `closePalette` / `openTweaks` / `closeTweaks` with focus restoration to the opener element; `closePalette` extended in Task 4 to reset target-pick state.
- **Sidebar** — `toggleSidebar` flips `[data-sidebar]` between `expanded` and `collapsed` and persists via `saveTweaks`.
- **Audit row expand** — `toggleAuditRow(id)` flips `aria-expanded` on the matching button + `hidden` on the matching body region.
- **Clipboard** — `copyClipboard(text)` prefers `navigator.clipboard.writeText`; falls back to a transient hidden textarea + `document.execCommand('copy')` for Safari / private mode / older browsers.
- **Bridge** — `registerDialogBridge(ref)` stores the .NET reference; `invokeDialog(commandId, targetId, targetName)` forwards to `_dotNetRef.invokeMethodAsync('OpenDialog', …)` and returns a Promise<bool>.
- **Tweaks click delegation** — single `document.addEventListener('click')` interprets `[data-tweak]` / `[data-value]` for radio-group rows + `[data-tweak-action="reset"]` for the reset button + scrim clicks for closing the palette/tweaks overlays.
- **Global keydown** — Cmd/Ctrl+K opens palette; Cmd/Ctrl+\\ toggles sidebar; ArrowUp / ArrowDown / Enter cycle aria-selected when `data-palette-open` is set on `<html>`; Esc closes both overlays.
- **Palette filter** — input handler narrows `button.palette-row` rows by case-insensitive substring match on `data-label`; collapses `palette-section` headers when no rows remain visible.
- **ARIA selection cycling** — `_visibleRows` / `_resetSelection` / `_moveSelection(±1)` / `_activateSelection` operate on visible rows; keyboard navigation wraps with modulo arithmetic.
- **Two-step target search (D-10)** — when an action row has `data-requires-target="true"`, palette enters `_selectedAction` state; subsequent keystrokes (≥2 chars) trigger `fetch('/admin/api/players/search?query=…', { credentials: 'same-origin' })` with AbortController-scoped cancellation; results render via `createElement` + `textContent`.
- **Dispatch** — `_dispatchOpenDialog` fires both `window.dispatchEvent('gamekit.admin.openDialog')` (host-app listener path) and `invokeDialog(...)` (Blazor bridge path).

## Bridge readiness for Plan 04

- `_dotNetRef` is registered exactly once per circuit (the `firstRender` guard prevents re-registration on subsequent renders).
- The `OpenDialog` invokable signature exactly matches the JS-side `_dispatchOpenDialog` payload: `(string commandId, Guid targetId, string targetName)`. JS passes empty string for actions without a target, which becomes `Guid.Empty` server-side — the dialog flow ignores it for `create-admin` (no target).
- The five wired commandIds (`ban`, `unban`, `gdpr-delete`, `create-admin`, `delete-admin`) cover the exhaustive Phase 03 dialog set. The two future commands (`rank-adjust`, `rotate-signing-key`) are mapped to `null` and silently no-op — they are filtered out at the registry layer (Plan 04) anyway.
- The CustomEvent path (`window.dispatchEvent('gamekit.admin.openDialog')`) is fire-and-forget for host-app integration; the dialog is launched through `invokeDialog` regardless.

## Test harness stub-ability

A bUnit / xUnit test that wants to stub the bridge can:

1. Render `MainLayout` inside `Bunit.TestContext` with `JSInterop.Mode = JSRuntimeMode.Loose` so `JS.InvokeVoidAsync("GKAdmin.registerDialogBridge", _selfRef)` records the call rather than executing it.
2. Inspect `JSInterop.VerifyInvoke("GKAdmin.registerDialogBridge")` to assert the bridge was registered.
3. Reach into the layout instance via `cut.Instance` and call `cut.Instance.OpenDialog("ban", playerId, "alice")` directly — the dialog dispatch flows through `Dialogs.ShowAsync(typeof(BanPlayerDialog), …)` which a `Mock<IDialogService>` can verify.

The `OpenDialog` switch is a pure data-driven dispatch — no IO, no async DB call — so unit testing the routing decisions is a single-arg `[Theory] + [InlineData]`.
