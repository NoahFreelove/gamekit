# Phase 03.1 Plan 08: Bulk re-skin (ChipRail + 8 pages + 5 dialogs + 5 shared components) Summary

**One-liner:** D-04 big-bang single-wave closeout — ships the new ChipRail filter
primitive (wired into Audit), re-skins every remaining `/admin/*` page + 5 shared
components + 5 dialogs to violet-600 sketch class names, and preserves the
load-bearing `Install GameKit.{Name}` substring contract that PanelRenderTests
depend on.

## What shipped

### Task 1 — ChipRail + Audit wire-up (commit 380dd8d)
- **`src/GameKit.Admin.UI/Components/Shared/ChipRail.razor`** (NEW): markup-only
  filter primitive. Renders `<div class="chip-rail" role="toolbar" aria-label="…">`
  containing one `<button class="chip" aria-pressed="…">` per
  `ChipItem(Value, Label, IsPressed)` record. Parent owns selection state via an
  `OnToggle` `EventCallback<string>`.
- **`src/GameKit.Admin.UI/Components/Shared/ChipRail.razor.css`** (NEW): only
  `:focus-visible` outline scoped here; bulk styling lives in global
  `gamekit-admin.css`.
- **`src/GameKit.Admin.UI/wwwroot/gamekit-admin.css`**: added `.chip.chip-active`
  rule + `button.chip` cursor/hover affordances. The pre-existing `.chip` /
  `.chip-rail` rules from Plan 02 cover the remainder.
- **`src/GameKit.Admin.UI/Components/Pages/Audit.razor`**: replaced the prior
  `MudSelect`-based filter row + Apply/Reset buttons with a single
  `<ChipRail Label="Filter by action" Chips="_actionChips" OnToggle="OnActionChipToggle" />`.
  Single-click toggle (clicking the active chip clears the filter); 7 chips for
  the 7 `AdminAuditActions` namespaces. The 2-column row expansion (Plan 07) and
  EnumerateDiff path are unchanged.

### Task 2 — 5 shared components + 5 dialogs (commit 374dead)
- **`MissingPackageAlert.razor`** (LOAD-BEARING — ADMIN-09): replaced `<MudAlert>`
  with sketch's `<div class="alert">` + `.alert-heading` / `.alert-body`. The
  literal text `Install GameKit.@PackageName and add .Add@(PackageName)(…)` is
  preserved byte-for-byte; PanelRenderTests `Assert.Contains("Install
  GameKit.Matchmaking", html)` and `Assert.Contains("Install GameKit.Rankings",
  html)` continue to pass.
- **`StatusChip.razor`**: `<MudChip>` → `<span class="chip {modifier}">` with a
  dot indicator; modifier maps OK/Active/Healthy/Online → `.healthy`, Degraded →
  `.degraded`, Down/Banned → `.down`, else `.info`.
- **`EnvironmentChip.razor`**: `<MudChip>` → `<span class="chip info">@Env</span>`.
- **`KeysetPaginator.razor`**: `<MudButton>` + `<MudProgressCircular>` →
  `<button class="btn">` + a CSS-only spinner span; new
  `KeysetPaginator.razor.css` for the wrapper layout + spinner keyframes.
- **`HealthTileView.razor`**: `<MudPaper>` → sketch's `<div class="health-tile">`
  with `.top` / `.v` / `.footer`; status chip pulls from the re-skinned
  StatusChip.
- **5 dialogs (Ban / Unban / CreateAdmin / DeleteAdmin / GdprDelete)**:
  added `Class="dialog dialog-danger"` (or `dialog-warn` for Unban) to
  `<MudDialog>`; swapped `gk-dialog-body` → `dialog-body`; dropped the
  `gk-dialog-danger-stripe` divs in favor of the wrapper class. `@code` blocks
  + `[CascadingParameter] IMudDialogInstance` + `@inject` directives + every
  `[Parameter]` declaration UNCHANGED. FluentValidation + CSRF + audit-write
  paths verified intact via the 19 BanPlayerRequest / CreateAdminRequest
  validator tests passing post-re-skin.
- **`gamekit-admin.css`** additions: `.alert .alert-heading` / `.alert-body`,
  `.alert:not(:has(.icon))` collapses the 2-col grid when no icon slot is
  used, and `.dialog` / `.dialog-danger` / `.dialog-warn` / `.dialog-body`
  wrapper rules.

### Task 3 — 7 pages + SideNav + LoginLayout (commit 71baa15)
- **`Dashboard.razor`**: direction-D 4-card grid per CONTEXT D-08 + sketch
  `dashboard.jsx`. `.grid-12` + `.span-6/8/4` utilities replace `MudGrid`;
  `.card` / `.card-head` / `.card-body` replace `MudPaper`; `.metric` /
  `.kv` / `.table.t` replace ad-hoc `gk-dashboard-*` divs. Reflective
  matchmaking-installed check + 4 EF queries on `OnInitializedAsync` are
  unchanged.
- **`Health.razor`**: `.page-head` + `.card` + `.grid-12` / `.span-4` around
  3 `<HealthTileView>` slots; refresh button is a plain `<button class="btn">`.
- **`Matches.razor`**: `.page-head` + `.empty` (empty states) + `.table-wrap`
  + `.t` (data table) + `.mono` cells. EF `from p in SessionParticipant join
  s in GameSessions ... where p.PlayerId == pid` query unchanged.
- **`QueueDepth.razor`** + **`RankAdjust.razor`**: `.page-head` heading +
  sketch `<div class="alert">` for the Phase-5/Phase-4 placeholder branch;
  `<MissingPackageAlert PackageName="Matchmaking|Rankings" Feature="..." />`
  call sites preserved verbatim.
- **`Admins.razor`**: `.page-head` with action button + `.table-wrap` /
  `.t` for the admin grid; role chip uses `.chip.role.{down|accent}` for
  visual differentiation; delete button is `.btn.btn-danger.btn-sm`;
  `<MudTooltip>` replaced with native `title=` attribute. Dialog launchers
  (`OpenCreateDialog` / `OpenDeleteDialog`) unchanged.
- **`Login.razor`**: left structurally untouched. The page is static-SSR
  (`[ExcludeFromInteractiveRouting]`); its `Login.razor.css` already
  references violet-aware `--accent` / `--bg` / `--surface` tokens; the
  form action `"/admin/login/submit"` is load-bearing (browser submits
  natively to set the auth cookie).
- **`SideNav.razor`**: `<MudNavMenu>` / `<MudNavLink>` → sketch's
  `<nav class="sidebar">` + Blazor `<NavLink class="nav-item">` per
  `shell.jsx`. `<AuthorizeView Roles="@AdminRoles.Superadmin">` wrappers
  around Rank-adjust + Admins rows PRESERVED verbatim.
- **`SideNav.razor.css`**: dropped `MudNavLink ::deep` selectors; added a
  thin `a.nav-item` color reset so the global `a { color: var(--accent); }`
  rule doesn't bleed into nav row labels.
- **`LoginLayout.razor`**: `MudThemeProvider` / `MudPopoverProvider` /
  `MudDialogProvider` / `MudSnackbarProvider` retained for parity with
  `MainLayout`. Scoped CSS already token-aware.
