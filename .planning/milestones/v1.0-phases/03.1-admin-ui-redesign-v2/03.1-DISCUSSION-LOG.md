## Component Implementation Strategy

### Round 1 — initial strategy pick

| Option | Description | Selected |
|--------|-------------|----------|
| Hybrid: MudBlazor for primitives, hand-roll the rest | Keep MudBlazor for MudDialog / MudSnackbar / MudForm / MudTextField; hand-roll shell + tables + new sketch components. Middle-of-road fidelity, retains validation/dialog plumbing. | |
| Pure re-skin: keep MudBlazor everywhere, override via theme + CSS | Update palette to violet, layer scoped overrides on every MudComponent. Lowest refactor surface, fastest delivery; visible Material residue. | |
| Pure hand-roll: drop MudBlazor from rendering path | Hand-roll every component to match sketch HTML/CSS verbatim; replace MudDataGrid, MudDialog, MudAutocomplete. Highest fidelity, highest effort. | ✓ (initial) |
| Other | — | |

**User's choice (initial):** Pure hand-roll: drop MudBlazor from rendering path
**Notes:** Subsequently reversed — see Round 2.

### Round 2 — reversal

User interrupted with: *"Instead lets not go full nuclear on its replacement but I really want it to look similar to the mockup"*

| Option | Description | Selected |
|--------|-------------|----------|
| Re-skin everything that already exists; only hand-roll the genuinely new sketch components | Keep all current MudBlazor usage (DataGrid / Dialog / Snackbar / Form / Layout / Drawer / AppBar). Heavy theme palette swap + scoped CSS overrides. Hand-roll only: command palette, Tweaks panel, master-detail Players, two-column Audit, ban banner, chip rail. | ✓ |
| Keep MudBlazor primitives, hand-roll the shell + tables | Keep MudDialog / MudSnackbar / MudForm / MudTextField. Hand-roll top nav + sidebar + tables + new sketch components. Higher fidelity, medium refactor surface. | |
| Other | — | |

**User's choice (final):** Re-skin everything that already exists; only hand-roll the genuinely new sketch components
**Notes:** Final decision for component strategy. Visual fidelity ceiling acknowledged (Material residue will leak through); preserves Phase 3 work and dialog/validation plumbing.

### Round 3 — JS layer

| Option | Description | Selected |
|--------|-------------|----------|
| Vanilla JS in wwwroot for client-fast primitives, Blazor for data-driven views | One static gamekit-admin.js owns palette / tweaks / density / clipboard / expand / sidebar. Blazor handles data + dialogs + forms. Avoids SignalR roundtrip on keystrokes. | ✓ |
| Pure Blazor Server + JS interop only where required | All state server-side; JS interop only for clipboard + global keydown listener. ⌘K palette + Tweaks toggles re-render via SignalR. Lag-prone on slow networks; FOUC on first paint. | |
| Other | — | |

**User's choice:** Vanilla JS in wwwroot for client-fast primitives, Blazor for data-driven views

## Tweaks Panel Persistence

### Round 1 — where state lives

| Option | Description | Selected |
|--------|-------------|----------|
| localStorage (sketch default) | Vanilla JS reads localStorage on first paint, applies [data-*] attributes before Blazor renders. No backend, no schema change. Lost across browsers. | ✓ |
| Per-admin DB column (admin_user_prefs jsonb) | Schema change: admin_users gains prefs jsonb. Durable across browsers/devices. Conflicts with ROADMAP's "no migration changes" scope. | |
| Signed cookie (gk_admin_tweaks alongside auth cookie) | Tweaks values serialized into a small DataProtection-signed cookie. Per-browser like localStorage but visible to the server (no FOUC). | |
| Other | — | |

**User's choice:** localStorage (sketch default)
**Notes:** Honors sketch + chat answer. Tradeoff (lost on browser change / no cross-device sync) accepted in exchange for sketch fidelity and zero-backend-change.

### Round 2 — ban-loudness scope

| Option | Description | Selected |
|--------|-------------|----------|
| Per-admin Tweak (default 'medium', localStorage) | Operator picks subtle / medium / loud and it sticks for them. Risk: subtle setting could miss a banned-player banner during investigation. | ✓ |
| Pinned per environment (always 'loud' in Production, no override) | Loudness server-controlled via GameKitAdminOptions.BanBanner.Loudness; not in Tweaks. Defends against the Production-subtle miss. | |
| Hybrid (Tweak available, Production has 'medium' floor — subtle disallowed) | Operator can flip medium↔loud in Production; subtle rejected with tooltip. | |
| Other | — | |

**User's choice:** Per-admin Tweak (default 'medium', localStorage)
**Notes:** Banner is never absent — subtle still renders the red border, just without the meta line.

### Round 3 — Tweak set scope (dashboard-direction)

| Option | Description | Selected |

## Command Palette Scope

### Round 1 — functional surface

| Option | Description | Selected |
|--------|-------------|----------|
| Navigation + tweaks toggles (no admin actions) | 10 routes + Tweak flips + Sign out. No mutations. Lowest risk. | |
| Navigation only (10 routes) | Pure router. Smallest scope. Loses verb-engine feel. | |
| Navigation + tweaks + admin actions | Action rows launch matching dialog (which owns CSRF + validation + audit). Highest UX win, biggest scope. | ✓ |
| Other | — | |

**User's choice:** Navigation + tweaks + admin actions

### Round 2 — target resolution

| Option | Description | Selected |
|--------|-------------|----------|
| Two-step flow (select action, then prompt for target inside palette) | Action selected → palette switches to search-list mode → user picks player → dialog opens with target pre-loaded. Mirrors Linear / Raycast / Slack. | ✓ |
| Context-aware only (actions only show when target implied by current page) | Actions on /admin/players/{id} only. Simpler; less powerful. | |
| Action with inline target chip (single-row expand) | 'Ban player…' row has a focusable target field. Denser UX; more JS state. | |
| Other | — | |

**User's choice:** Two-step flow

### Round 3 — role gating

| Option | Description | Selected |
|--------|-------------|----------|
| Hide superadmin-only actions for plain admins | Palette filter discards rows the operator can't perform. Mirrors SideNav route gating. | ✓ |
| Show but disabled with 'Requires superadmin' hint | Row visible, dimmed. Better discoverability; mild info-disclosure. | |
| Other | — | |

**User's choice:** Hide superadmin-only actions for plain admins

## Audit Sentence Generation

### Round 1 — where the template lives

| Option | Description | Selected |
|--------|-------------|----------|
| Server-side per-action templates registered alongside AdminAuditActions; sentence on read API | (Actor, Target, Before, After) → SentenceModel projected into GET /admin/api/audit. Testable, localizable later, reusable. | ✓ |
| Client-side Razor switch on action namespace | AuditRow.razor switch renders sentence inline. No server changes. Razor-coupled; harder to localize. | |
| Generic 'actor action target' renderer (omit per-action niceties) | One template: '{Actor} {Verb} {Target}{Reason}'. Lowest effort, lowest fidelity. | |
| Other | — | |

**User's choice:** Server-side per-action templates registered alongside AdminAuditActions

### Round 2 — when the sentence is computed

| Option | Description | Selected |
|--------|-------------|----------|
| Read time (template runs on each GET; stored row unchanged) | admin_audit_log keeps existing schema. Template improvements apply retroactively. Honors ROADMAP "no migration changes" constraint. | ✓ |
| Write time (sentence rendered into a column on insert) | Schema migration; historical rows need backfill. Conflicts with phase scope. | |
| Other | — | |

**User's choice:** Read time

### Round 3 — fallback for unmapped actions

| Option | Description | Selected |
|--------|-------------|----------|
| Generic fallback sentence + raw structured diff | Left: '{Actor} performed {Action} on {Target}{Reason}'. Right: raw JsonElement diff key-by-key. Operator never sees a blank cell. | ✓ |
| Throw startup assertion (every action must have template) | Strict. Forces governance. Adds friction when introducing new admin actions. | |
| Render only structured diff (left column shows action tag only) | No fallback sentence. Cleaner; less informative. | |
| Other | — | |

**User's choice:** Generic fallback sentence + raw structured diff
