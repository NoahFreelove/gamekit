# Phase 03.1: Admin UI redesign v2 — Pattern Map

**Mapped:** 2026-05-01
**Files analyzed:** 41 (5 NEW Razor + 1 NEW JS + 5 NEW services/DTOs + 7 NEW tests + 5 MUTATED + 18 RE-SKIN)
**Analogs found:** 41 / 41 — every file has a same-file or strong sibling analog because Phase 03 already shipped the entire admin RCL

The single most important context: **this phase is a re-skin of an existing package**, not a greenfield build. Every MUTATED / RE-SKIN file's analog is its own current contents; the planner instructs the executor to *retain markup contracts* and *swap classes / palette / density* via CSS + new CSS custom properties. Genuinely NEW components (CommandPalette, TweaksPanel, BanBanner, ChipRail, PlayerDetailPane) borrow shape from the closest sibling Razor + the sketch's JSX reference.

**One pattern dominates this phase:** *CSS custom properties from the sketch (`--accent`, `--bg`, `--surface`, `--row-h`, …) replace literal MudBlazor / `--gk-*` tokens; `[data-accent]` / `[data-density]` / `[data-sidebar]` / `[data-ban-loud]` attribute selectors on `<html>` swap the values at runtime; vanilla JS in `gamekit-admin.js` writes those attributes from `localStorage.gamekit.admin.tweaks`; the inline init `<script nonce="@Nonce">` in `App.razor`'s `<head>` runs before `<body>` paint to avoid FOUC.*

group.MapGet("/commands", (HttpContext http, AdminCommandRegistry reg) =>
{
    var role = http.User.FindFirst(ClaimTypes.Role)?.Value ?? AdminRoles.Admin;
    var visible = reg.AllCommands
        .Where(c => !c.RequiresSuperadmin || role == AdminRoles.Superadmin)
        .Select(c => new { c.Id, c.Label, c.Category, c.RequiresTarget })
        .ToArray();
    return Results.Ok(visible);
}).RequireAuthorization(AdminPolicies.Admin);

private async Task OnPaletteOpenDialog(string commandId, Guid targetId, string targetName)
{

    var reference = commandId switch
    {

}
