## 5. Component-by-Component Contracts

### 5.1 CommandPalette.razor

**Open/close:** ⌘K (or Ctrl+K) toggles. Esc closes, restoring focus to opener. `<div role="dialog" aria-modal="true" aria-label="Command palette">`.

**States:** `idle` (no input) → shows recent + nav rows. `filtering` (text typed) → substring filters all rows. `target-pick` (action selected requiring target) → renders search-list backed by `IPlayerSearchService` (D-10).

**Action registry:** static C# `AdminCommandRegistry` exposes a JSON endpoint `GET /admin/api/commands` → array of `{ id, label, category, requiresSuperadmin, requiresTarget }`. Vanilla JS fetches once on first open, caches per session. Server filters by current operator's role BEFORE serializing (D-11) — superadmin-only rows simply absent for non-superadmins; never grayed.

**Action set (v1):** ban / unban / GDPR-delete / create-admin (super) / delete-admin (super) / rank-adjust (Phase 4 placeholder if `GameKit.Rankings` missing) / rotate-signing-key (super, Phase 2) / sign-out + 10 nav rows.

**Two-step flow (D-10):** action with `requiresTarget=true` → JS clears input, swaps placeholder to "Search players…", calls `fetch('/admin/api/players/search?q=…')`, renders results in same `role="listbox"`. Selecting a target closes the palette and dispatches a `gamekit.admin.openDialog` `CustomEvent` that a `DotNetObjectReference` registered on `MainLayout` consumes to launch the matching `MudDialog` with `Id` parameter.

**Keyboard (per RESEARCH § Accessibility):** ↑/↓ moves active row, Enter invokes, Tab cycles input ↔ list, Esc closes.

**Search algorithm:** substring match (case-insensitive, accent-folded) on `label` + `category`. No fuzzy matcher in v1 (assumption A8).

### 5.2 TweaksPanel.razor

**Surface:** opens via top-nav button (per sketch); rendered as a right-side drawer or popover.

**Body:** 5 sections (accent, density, sidebar, ban-loudness, dashboard-direction). Each renders `<button type="button" role="radio" aria-checked="…">` per option (sketch convention; port verbatim).

**Storage:** single localStorage key `gamekit.admin.tweaks` holding JSON `{ accent, density, sidebar, banLoud, dashDir }`. JS owns read/write/apply on `<html>`. Reset-to-defaults button at panel footer (sets to defaults from §2 + clears localStorage).

**`dashboard-direction`:** picker visible with A/B/C disabled (`disabled aria-disabled="true"`) + tooltip "coming soon" (D-08).

### 5.3 BanBanner.razor

**Render rules (CONTEXT D-07; sketch lines 590-610):**

| `[data-ban-loud]` | Visual |
|-------------------|--------|
| `subtle` | 3px red left border + bold reason on `--surface`; meta line hidden |
| `medium` (default) | Full red banner: `--red-bg`, `--red-border`, 3 lines (reason / actor / timestamp) |
| `loud` | Same as medium + 2px outer ring (`box-shadow: 0 0 0 2px var(--red)`) + larger reason font (16→18px) |

**ARIA:** `role="alert" aria-live="polite"` (sketch convention).

**Cascade param:** `[CascadingParameter] BanLoudness Loud { get; set; }` from `MainLayout` reading `[data-ban-loud]` from JS-applied root attribute. Banner reads attribute on mount; no re-render on tweak change required (page navigates after).

### 5.4 ChipRail.razor

Filter primitive for Audit (action namespace + actor + date range) and Players (status + identity provider).

**Markup:** `<div class="chip-rail" role="toolbar" aria-label="Filters">` containing `<button class="chip" aria-pressed="…">…</button>` per chip.

**Persistence (Claude's Discretion per CONTEXT):** session-only via component state. URL query string sync deferred — too much scope for the redesign wave.

### 5.5 Audit two-column row treatment

**Left column (`<div class="sentence">`):** Razor renders from `SentenceModel { Intro, Target, Modifier, Reason }`. Layout: `<strong>{Actor}</strong> {Intro} <strong>{Target}</strong>{Modifier ? " " + Modifier : ""}{Reason ? " — " + Reason : ""}`. Reason is truncated at ~60 chars; full text in expanded state.

**Right column (`<div class="diff">`):** Renders before/after `JsonElement` key-by-key. Each row: `<span class="diff-key">{key}</span> <span class="diff-before">{before}</span> → <span class="diff-after">{after}</span>` with `[data-diff-state="added|removed|changed"]` for color coding.

**Toggle:** existing `<button aria-expanded>` triggers expand. Two-column treatment lives inside the row's expanded body; collapsed shows only the sentence + chevron.

**Sentence registry (D-12):** static `AuditSentenceTemplates` dict `IReadOnlyDictionary<string, AuditSentenceTemplate>` keyed on `AdminAuditActions.*` constants. Templates implement `Render(string actor, string? target, JsonElement? before, JsonElement? after, string? reason) → SentenceModel`. Generic fallback (D-14): `new SentenceModel(Intro: "performed", Target: action.Replace('.', ' '), Modifier: null, Reason: reason)`.

**API change:** `GET /admin/api/audit` response DTO gains a `sentence: SentenceModel` field per row. No DB schema change (D-13).

### 5.6 Players master-detail (Players.razor)

**Layout:** `[grid-template-columns: 360px 1fr]` (compact) / `[400px 1fr]` (comfortable).

**Left (master):** persistent search input + chip rail (status filter) + `KeysetPaginator`-backed list. Selecting a row updates URL to `/admin/players/{id}` via `NavigationManager.NavigateTo` (preserve list scroll position via Blazor `enhanced` nav).

**Right (detail):** `PlayerDetailPane.razor` receives `[Parameter] Guid? Id`. When `Id` is null, render empty state: "Select a player from the list →". When present, fetch + render: ban banner (if banned) + identities + actions panel (Ban / Unban / GDPR / RankAdjust buttons; permission-gated).

**Deep linking:** `/admin/players/{id}` enters with both panes populated. List highlights the selected row.

### 5.7 Dialogs (5 — re-skin only)

API + DI + CSRF + audit-write paths UNCHANGED from Phase 03. Only `MudDialog` style overrides + density tokens applied.

## 8. Accessibility Contract (WCAG 2.1 AA)

Follows `03.1-RESEARCH.md` § Accessibility (computed contrast ratios). Specific obligations:

- All `:focus-visible` states use 2px solid `var(--accent)` outline at ≥ 3:1 against any background the focusable element appears on (verified: 5.20-5.70:1 across all surface tokens).
- `--fg-3` swapped from sketch's `#94A3B8` (2.45:1) → `#64748B` (4.69:1) — see §1.2.
- All interactive components have keyboard equivalents (§7).
- Banner: `role="alert" aria-live="polite"`.
- Palette: `role="dialog" aria-modal="true"` with focus trap + `role="listbox"` results.
- Audit toggle: `<button aria-expanded>`.
- Tweaks options: `role="radiogroup"` with `<button role="radio" aria-checked>`.
- All chips/buttons have visible labels (no icon-only without `aria-label`).

Manual axe DevTools sweep at 1280px is part of Wave 6 (per VALIDATION.md § Manual-Only Verifications).
