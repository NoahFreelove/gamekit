<objective>
Wire the Rankings package into a host application via the fluent builder pattern, register ladders at startup, and ship the service-token authentication scheme + CLI verbs that gate the session-complete endpoint (consumed by plan 04-05).

Purpose: This plan closes RANK-09 (AddLadder API) and lays the auth foundation for RANK-11 (session-complete). Output: AddRankings / AddLadder fluent surface, StartupLadderUpserter, ServiceTokenAuthenticationHandler + options + scheme constants + authorization policy, three CLI verbs (issue/revoke/list), RankingsCliModelCustomizer to defend against Pitfall 3.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI stdout → operator | Raw service token printed once; operator transports out-of-band; never re-printable |
| HTTP Authorization header → service-token table | Custom AuthenticationHandler crosses untrusted-network → trusted-DB boundary on every session-complete call |
| AddLadder caller → ladders table | Build-time fluent API serializes config into Postgres at startup; first-write-wins |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-RT | Spoofing | Raw service token stored at rest | mitigate | ServiceTokenService stores only SHA-256 hash; raw is printed exactly once via AnsiConsole.MarkupLine. Test ServiceTokenCommandsTests.ListCommand_Does_Not_Print_Token_Hash asserts hash never leaks via ListAsync. |
| T-04-04-RV | Spoofing | Revoked token continues authenticating | mitigate | ServiceTokenAuthenticationHandler checks RevokedAt is null AND ExpiresAt is in the future before returning Success. Test RevokedToken_Returns_401 anchors. |
| T-04-04-BF | Spoofing | Token brute-force | mitigate | 32 bytes CSRNG = 256 bits entropy; rate-limit gamekit:sessions:complete = 300/min/token (plan 04-05); no enumeration endpoint. |
| T-04-04-DR | Denial of Service | Service-token lookup DB hot-read at high QPS | accept | v1 accepts the DB hit per Pitfall 10 — rate limit 300/min/token keeps load tractable. XML doc TODO points at v2 IMemoryCache optimization. |
| T-04-04-DU | Tampering | AddLadder called twice with same name on first deploy | mitigate | AddLadder builder throws ArgumentException on duplicate name at registration time; StartupLadderUpserter uses SELECT-then-INSERT pattern inside SERIALIZABLE tx so concurrent replicas race safely. Test LadderUpsertOnStartupTests.AddLadder_Inserts_Row_Idempotently asserts re-run produces one row. |
| T-04-04-MC | Tampering | EF Core global model cache crashes CLI on missing Rankings entity | mitigate | RankingsCliModelCustomizer replaces IModelCustomizer at DbContextOptionsBuilder time per Pitfall 3 (mirrors AdminCliModelCustomizer). |
| T-04-04-AC | Spoofing | Player JWT authenticates against service-token policy | mitigate | RequiresServiceToken policy specifies AddAuthenticationSchemes(SchemeName).RequireRole("service-account"). Player JWT scheme issues different roles, so RequireRole fails the policy. Plan 04-05's test SessionComplete_PlayerJWT_Returns_403 anchors. |
</threat_model>
