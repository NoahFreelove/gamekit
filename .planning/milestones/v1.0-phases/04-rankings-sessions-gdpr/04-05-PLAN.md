<objective>
Wire the session-complete endpoint in GameKit.Core (per D-22), the TWO ports that Rankings consumes (IPostSessionCompleteHandler for the rating-update enqueue + IIdempotencyStore for body-hash dedup persistence), the CanonicalJsonHasher for idempotency body dedup (Open Q5), the generic IdempotencyKeyEndpointFilter and ValidationEndpointFilter primitives (both in Core — they are not Rankings-specific), and the rate-limit policy. This plan delivers RANK-11 and SC#2 (5x retry → exactly one rating delta).

Purpose: The session-complete endpoint is the single most subtle HTTP surface in Phase 4. The state-conditional UPDATE pattern (D-07) + idempotency-key dedup (D-08) + body canonicalization (Open Q5) + port-based enqueue (D-22) all interact inside one transaction. Getting it right gates the ticker (plan 04-06) and SC#2. The checker-flagged BLOCKER (filters wired into Core but living in Rankings) is corrected here: the endpoint filters live in Core because they are generic primitives; the persistence side of idempotency dedup is the only part that lives in Rankings, behind the new IIdempotencyStore port — same shape as D-22's IPostSessionCompleteHandler.

Output: Endpoint in Core that lives behind the GameKitServiceToken policy, with the Rankings package supplying TWO adapter impls (post-completion enqueue + idempotency persistence) through ports; idempotency dedup at the DB level (24h TTL row); 300/min/token rate limit; comprehensive SC#2 test.
</objective>
