## Decisions Made

- **EmitCompilerGeneratedFiles=true at Directory.Build.props (added in Task 4 commit, NOT Task 2):** the Task 4 `<verify>` step uses `find ... -name GameKitMarker.g.cs` to confirm the generator emits a non-fallback version. Roslyn defaults `EmitCompilerGeneratedFiles=false`, keeping output in-memory only. Enabling it repo-wide also gives the Plan 06-08 OPS-04 / OPS-05 disk-asserting tests something to inspect alongside the compiled IL. Files land in `obj/.../generated/...` which is `.gitignore`-d already.
- **CompilerGeneratedFilesOutputPath NOT overridden:** an initial attempt to set `CompilerGeneratedFilesOutputPath=$(BaseIntermediateOutputPath)$(Configuration)\$(TargetFramework)\generated` (with Windows backslashes) on Linux produced a non-`obj/` path that fell inside the SDK's default Compile glob, surfacing CS0102 duplicate-definition errors. Reverting to the Roslyn default location (`obj/$(Configuration)/$(TargetFramework)/generated/{GeneratorAssembly}/{GeneratorFQN}/`) avoids the glob.
- **GameKit.OpenApi/AssemblyInfo.cs does NOT declare [assembly: AssemblyDescription]:** the SDK auto-emits `AssemblyDescriptionAttribute` from the `<Description>` element of the csproj. A manual `[assembly: AssemblyDescription(...)]` declaration alongside the auto-emitted one produces CS0579. The csproj `<Description>` is the canonical source; the AssemblyInfo.cs file only carries the SPDX header + the `InternalsVisibleTo` directive that the SDK does not auto-emit.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added `EmitCompilerGeneratedFiles=true` to `Directory.Build.props`**
- **Found during:** Task 4 (smoke verify `find ... GameKitMarker.g.cs` returned empty)
- **Issue:** Plan's automated `<verify>` step depends on the generator output being on disk. By default Roslyn keeps generator output in-memory; the file never appears under `obj/`.
- **Fix:** Added `<EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>` to `Directory.Build.props` PropertyGroup with comment block explaining the rationale (also useful for Plan 06-08 OPS-04 / OPS-05 disk-asserting tests).
- **Files modified:** `Directory.Build.props`
- **Verification:** After rebuild, `find src/GameKit.Core/obj -name GameKitMarker.g.cs` returns the expected path and the file contains `GameKitVersion = "1.0.0"`.
- **Committed in:** `6742467` (Task 4 commit).

**2. [Rule 1 - Bug] Removed `[assembly: AssemblyDescription(...)]` from `src/GameKit.OpenApi/AssemblyInfo.cs`**
- **Found during:** Task 4 (build of `src/GameKit.OpenApi/` failed with CS0579)
- **Issue:** Plan called for adding `[assembly: System.Reflection.AssemblyDescription(...)]` in `AssemblyInfo.cs`. The .NET SDK's `GenerateAssemblyInfo` already auto-emits `AssemblyDescriptionAttribute` from the csproj `<Description>` element into `obj/.../GameKit.OpenApi.AssemblyInfo.cs`. Having both produces a CS0579 duplicate-attribute error.
- **Fix:** Replaced the manual `[assembly: AssemblyDescription(...)]` with a comment block explaining the SDK auto-emission. Retained the `[assembly: InternalsVisibleTo("GameKit.OpenApi.Integration.Tests")]` directive (which is NOT auto-emitted by the SDK and is needed by Plan 06-06 transformer tests).
- **Files modified:** `src/GameKit.OpenApi/AssemblyInfo.cs`
- **Verification:** `dotnet build -c Debug src/GameKit.OpenApi/GameKit.OpenApi.csproj` returns 0 warnings, 0 errors. The compiled DLL's metadata description matches the csproj `<Description>` text.
- **Committed in:** `6742467` (Task 4 commit).

**3. [Rule 1 - Bug] Reverted `CompilerGeneratedFilesOutputPath` override**
- **Found during:** Task 4 (initial attempt to enable EmitCompilerGeneratedFiles also set `CompilerGeneratedFilesOutputPath=$(BaseIntermediateOutputPath)$(Configuration)\$(TargetFramework)\generated` and produced CS0102 duplicate-definition errors)
- **Issue:** The override path contained Windows backslashes that on Linux did not combine into an `obj/`-rooted path. The resulting `src/GameKit.Core/Debug/net10.0/generated/...` location fell inside the SDK's default `<Compile Include="**\*.cs">` glob, so the generated file was BOTH `AddSource`-d into the compilation AND `<Compile>`-d as a regular source — producing CS0102 duplicate definitions for `GameKitVersion` and `AssemblyName`.
- **Fix:** Removed the `CompilerGeneratedFilesOutputPath` override; Roslyn defaults to `obj/{Configuration}/{TargetFramework}/generated/{GeneratorAssembly}/{GeneratorFQN}/` which the SDK explicitly excludes from the Compile glob.
- **Files modified:** `Directory.Build.props` (revert inside the same edit cycle as deviation #1)
- **Verification:** Clean rebuild of `src/GameKit.Core/` succeeds; `obj/Debug/net10.0/generated/GameKit.Build/GameKit.Build.GameKitVersionGenerator/GameKitMarker.g.cs` is on disk and is NOT pulled into the compile glob a second time.
- **Committed in:** `6742467` (Task 4 commit).
