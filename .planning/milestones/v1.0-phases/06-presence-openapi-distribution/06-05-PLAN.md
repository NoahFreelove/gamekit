<objective>
Ship the two new session lifecycle endpoints (`POST /api/sessions/{id}/start` and `POST /api/sessions/{id}/abandon`) that Phase 4 left as future work and Plan 06-04 already prepared the observer wiring for. These endpoints close PRES-05 (game-server-authoritative in-match transition) and reconcile the ROADMAP SC#1 wording fix from Plan 06-01 with actual runtime behavior.

Purpose: D-20 explicitly states Phase 6 must ship these endpoints — they do NOT exist today (only /complete from Phase 4 — PATTERNS warning #12). The endpoints are the game-server's only mechanism for transitioning a session into / out of the Active state, which is the only mechanism for setting / clearing the Redis in-match marker. Without them, the Lua precedence rule from Plan 06-04 has nothing to defend against (no one is writing "in_match" values), and PresenceSessionObserver is wired but never invoked.

Output: 2 new service implementations + 2 new request DTOs + extended SessionEndpoints + extended AddGameKit DI registration + extended SessionCompleteService (inject + invoke observers) + 3 integration tests (one per endpoint + end-to-end observer wiring proof in Presence.Integration.Tests).
</objective>
