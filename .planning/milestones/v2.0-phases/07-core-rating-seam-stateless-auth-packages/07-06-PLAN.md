<objective>
Complete AUTH-18 by wiring the rehash-on-verify call site: in `PasswordOAuthProvider.CompleteLoginAsync`, after a successful `_hasher.Verify(...)` and before token issuance, call `_hasher.NeedsRehash(credential.PasswordHash)` and, when true, re-hash the password and UPDATE `player_credentials.password_hash` in the same request scope. Then prove it end-to-end with a Testcontainers Postgres integration test: a player created with a BCrypt hash logs in under an Argon2-configured host and ends up with an `$argon2id$` hash.

Purpose: This is the call site that makes the Argon2 migration actually happen. Without it, `Argon2idPasswordHasher.Verify` succeeds on a BCrypt hash and `NeedsRehash` returns true, but the column never migrates (RESEARCH §Pitfall 3). The default BCrypt hasher returns false from NeedsRehash so existing behaviour is unchanged.

Output: one modified provider file + one new integration test class. ZERO migrations.

Depends on Plan 02 (07-02) because it consumes `IPasswordHasher.NeedsRehash` (added there) and the integration test references `GameKit.Auth.Argon2`'s `Argon2idPasswordHasher` / `UseArgon2()`. Modifies only `PasswordOAuthProvider.cs` + a new test file — NO file overlap with Plans 03/04/05; runs parallel with them in Wave 2.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| login request → PasswordOAuthProvider | Untrusted plaintext password crosses in; on success the rehash path rewrites the stored credential. |
| rehash UPDATE → player_credentials | The migration write must commit in the same request transaction or never happen. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-06-01 | Tampering | Rehash never persists → BCrypt hashes never migrate (silent) | mitigate | The UPDATE runs inside CompleteLoginAsync's request-scoped DbContext with an explicit SaveChangesAsync; the integration test re-reads from a fresh scope to prove durability (RESEARCH §Pitfall 3). |
| T-07-06-02 | Information Disclosure | Rehash on the user-not-found path leaks account existence (timing/side-effect) | mitigate | The rehash block is placed only after a successful Verify against a real credential row; the dummy-hash user-not-found path is untouched. Code-review acceptance criterion + control test confirm no behavioural change under the default hasher. |
| T-07-06-03 | Elevation of Privilege | Rehash UPDATE accidentally rewrites another player's credential | mitigate | The tracked re-load filters by `c.PlayerId == credential.PlayerId`; the integration test asserts the specific seeded row migrated and login returned that player's tokens. |
| T-07-06-SC | Tampering | npm/pip/cargo installs | n/a | No new package installs in this plan (consumes the Argon2 package + pins added by Plan 02). No legitimacy checkpoint required. |
</threat_model>
