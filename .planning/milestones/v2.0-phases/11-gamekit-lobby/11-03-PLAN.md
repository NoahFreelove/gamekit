<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client WebSocket upgrade → JwtBearer middleware | Untrusted upgrade request; token arrives in the `access_token` query string (browsers cannot set WS Authorization headers). Validated before the handshake completes. |
| client hub invocation → LobbyHub | Untrusted method args (lobbyId, message) cross here; membership + length must be validated server-side. |
| LobbyHub relay → SignalR group | Chat content relayed as opaque string; never executed or persisted by GameKit. |
| MarkReady all-ready transition → matchmaking trigger | Only lobby members can trigger; transition is concurrency-controlled. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03-01 | Spoofing | unauthenticated WebSocket upgrade to /hubs/lobby | mitigate | LobbyJwtBearerPostConfigure reads access_token from QS for /hubs/lobby; JwtBearer returns 401 before handshake when token absent/invalid; [Authorize] on LobbyHub is the second layer (SC#2). |
| T-11-03-02 | Elevation of Privilege | player joins/sends to a lobby they are NOT a member of | mitigate | JoinLobbyAsync + SendChatMessageAsync call ILobbyService.IsMemberAsync (server-side DB check) before AddToGroupAsync / relay; HubException on failure. Client-supplied lobbyId is never trusted. |
| T-11-03-03 | Tampering | chat message persistence / injection | mitigate | SendChatMessageAsync performs zero Postgres writes; ILobbyMessageHandler has no persistence method (relay/gate only); raw string relayed — XML doc assigns safe-rendering to the consuming client; MaxChatMessageLength caps message size. |
| T-11-03-04 | Denial of Service | chat flooding | mitigate | Hub-side MaxChatMessageLength check + ILobbyMessageHandler.OnMessageAsync can return false to suppress (rate-limit extension point); documented for consumers. |
| T-11-03-05 | Spoofing | player identity in hub | mitigate | GetPlayerId extracts sub/NameIdentifier from Context.User (the validated JWT principal); ICurrentPlayer deliberately not used (HttpContext null in hub → would NRE/return null). |
| T-11-03-06 | Tampering / DoS | concurrent double ready-check transition | mitigate | MarkReadyAsync uses SERIALIZABLE + 40001 retry + state==ReadyChecking guard inside the tx — only one transition submits. |
| T-11-03-SC | Tampering | NuGet installs | accept | No new package installs in this plan (pins added in Plan 01); first-party Microsoft SignalR packages already verified. |
</threat_model>
