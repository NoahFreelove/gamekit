<objective>
Close out ADMIN-14 / SC#1: make the Admin health-panel "recent error rate" tile correct across replicas by adding a Redis-backed error counter that aggregates `INCRBY` on per-second time-bucketed keys. This is ADDITIVE — `ErrorRateRingBuffer` + `LogErrorCounter` stay in place as the local in-memory write side; the Redis counter is an opt-in second write destination active only when an `IConnectionMultiplexer` is registered. Single-instance installs are unchanged.

Purpose: In a multi-replica deployment each process has its own in-memory ring buffer, so the health tile under-reports — it only sees errors on the replica serving the request. Redis gives all replicas one shared counter to write to and read from, so the tile reflects the true cross-fleet error rate.

Output: `IRedisErrorRateCounter` + `RedisErrorRateCounter` (new), `LogErrorCounter` dual-write (modified), `HealthProbeService.ProbeErrorRate` becomes async and prefers the Redis aggregate (modified), conditional registration in `AddGameKitAdmin` (modified), and a two-host cross-replica integration test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin server replicas → Redis | All replicas write/read the shared error-rate counter keys |
| Redis counter → health tile | Aggregate count drives the operator-facing health status |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-03-DOS | Denial of Service | Redis unavailable while logging errors / probing health | mitigate | Writes are fire-and-forget with swallow-all try/catch (never throw into the logger pipeline); RecentErrorCountAsync returns -1 on failure and HealthProbeService falls back to the in-memory ErrorRateRingBuffer — no hang, no crash |
| T-12-03-TAM | Tampering | Redis error-counter integer overflow | accept | INCRBY operates on int64; per-second bucket TTL = window + 1 bucket auto-expires keys; overflow is not a realistic risk (RESEARCH §Known Threat Patterns) |
| T-12-03-TAM2 | Tampering | Attacker-influenced Redis key name | mitigate | Key schema is a fixed literal `gamekit:admin:errors:{epoch_bucket}` derived only from server clock + configured bucket width — no user input enters the key |
| T-12-03-INF | Information Disclosure | Error counts leaking sensitive data | accept | The counter stores only integer counts; no error message, payload, or PII is written to Redis |
| T-12-03-SC | Tampering | npm/pip/cargo/NuGet installs | accept | No new packages (RESEARCH §Package Legitimacy Audit: SignalR.StackExchangeRedis + StackExchange.Redis already pinned from Phase 11; zero new deps) |
</threat_model>
