<objective>
Close out ADMIN-13 / SC#2: add an `AdminEventHub` SignalR hub on a Redis backplane so admin live events reach every connected admin session regardless of which replica they land on. An `AdminLiveBroadcastService` `BackgroundService` subscribes to Redis Pub/Sub channel `"gamekit:admin:events"` and relays each message to connected admin clients via `IHubContext<AdminEventHub>`. The hub is gated by the `GameKitAdmin` COOKIE scheme (`[Authorize(Policy = AdminPolicies.Admin)]`) — a player JWT must NOT be able to connect. Also ship the multi-replica ops guide (sticky sessions, Redis backplane, shared Data Protection key ring).

Purpose: Multi-replica Admin UI requires cross-instance message delivery. The Redis backplane (NEVER Azure SignalR — GPL zero-cloud constraint) reuses the exact pattern proven in Phase 11 GameKit.Lobby. The key security boundary is auth-scheme isolation: admins authenticate via the `gk_admin_session` cookie, never the player Bearer token.

Output: `AdminEventHub` (new hub), `AdminLiveBroadcastService` (new BackgroundService), `AdminBackplanePostConfigure` (new — mirrors LobbyRedisBackplanePostConfigure), registration in `AddGameKitAdmin`, hub mapping in `MapGameKitAdmin` under MountPath, `docs/ops/multi-replica.md`, and an integration test proving cookie-only auth + cross-replica backplane relay.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → AdminEventHub (WebSocket) | Untrusted client attempts the SignalR negotiate + WS upgrade |
| Redis Pub/Sub → AdminLiveBroadcastService → all admin sessions | Relayed payload fans out to every connected admin |
| replica A → Redis backplane → replica B | Cross-instance message delivery |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-04-SPOOF | Spoofing | Player JWT authenticating the AdminEventHub | mitigate | `[Authorize(Policy = AdminPolicies.Admin)]` pins the GameKitAdmin cookie scheme; JWT Bearer cannot satisfy it; SC#2 test (b) empirically asserts a player JWT is refused (extends Phase 3 CrossSchemeIsolationTests to the new endpoint) |
| T-12-04-SPOOF2 | Spoofing | Unauthenticated WebSocket upgrade | mitigate | Hub mapped under MountPath so the path-based scheme selector routes /admin/hubs/events to the cookie scheme; unauthenticated upgrade returns 401 before handshake (SC#2 test (a)) |
| T-12-04-INF | Information Disclosure | Admin event payload leaking sensitive data to all admin sessions | mitigate | Hub is admin-only (cookie scheme + role admin/superadmin); only admins receive events; in Phase 12 the only publisher is the SC#2 test (no PII on the channel); future publishers must scope payloads to what admins may see (documented in XML remarks) |
| T-12-04-TAM | Tampering | Attacker-influenced Redis channel name | mitigate | Channel is the fixed literal "gamekit:admin:events"; no user input enters the channel name; ChannelPrefix "GameKit" isolates GameKit channels from consumer SignalR |
| T-12-04-DOS | Denial of Service | Admin event flooding / a single malformed relay killing the service | mitigate | AdminLiveBroadcastService swallows per-message relay errors and only returns on shutdown cancellation; one bad message cannot kill the relay; admin-only publish path is not consumer-accessible (low risk, accepted residual) |
| T-12-04-SES | Session Management | Multi-replica admin cookie rejected by a sibling replica (no shared Data Protection keys) | mitigate | docs/ops/multi-replica.md documents the mandatory shared Data Protection key ring (PersistKeysTo*) + sticky sessions; ADMIN-13 documentation deliverable |
| T-12-04-SC | Tampering | npm/pip/cargo/NuGet installs | accept | No new packages (RESEARCH §Package Legitimacy Audit: Microsoft.AspNetCore.SignalR.StackExchangeRedis 10.0.8 + SignalR.Client already pinned from Phase 11; zero new deps) |
</threat_model>
