<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ticker code → metric tags | tag keys/values cross into the export path; PII here leaks to Prometheus |
| ObservableGauge callback → Redis | scrape-time `ZCARD` fan-out is a potential DoS / failure-amplification vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-02-PII | Information Disclosure | new matchmaking metric tags | mitigate | Only `pool.name`, `ladder.id`, `reason` used as tag keys — all low-cardinality, non-PII, from `GameKitTelemetry` constants. GK0001 analyzer (build) + `MatchmakingPiiTagKeyTests` (runtime, this plan) enforce the forbidden set (criterion #1). |
| T-15-02-DOS | Denial of Service | QueueDepth ObservableGauge Redis reads on scrape | mitigate | Bounded pool count (operator-fixed at startup: default + AllowedRegions, ~3–9 keys); synchronous `IDatabase.SortedSetLength` (no thread-pool starvation); try/catch yields no measurement on `RedisException` (Pitfall 3) so a Redis blip never throws out of the scrape pipeline. Prometheus default 15–30s scrape bounds frequency (RESEARCH cost analysis: <1ms/scrape). |
| T-15-02-CARD | Denial of Service | unbounded instrument cardinality | mitigate | No high-cardinality tag (no per-ticket/per-player dimension); `ladder.id`/`pool.name` are operator-configured and finite. |
| T-15-02-SC | Tampering | package installs | accept | No new packages — in-box `System.Diagnostics.Metrics` + already-pinned StackExchange.Redis. |
</threat_model>
