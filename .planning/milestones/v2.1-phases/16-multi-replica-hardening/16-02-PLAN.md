<objective>
Add a Postgres-level secondary guard against split-brain duplicate match creation: an `IdempotencyKey` column on `game_sessions` with a partial unique index, set at match-formation time to the proposal id, written via `INSERT … ON CONFLICT DO NOTHING`. This is the SCALE-03 implementation. The atomic Lua claim script is the primary guard; this column is the last line of defense so that even if two replicas both believe they are leader for one proposal, Postgres admits exactly one `game_sessions` row.

Purpose: Survive the split-brain double-write window with a durable, atomic, no-distributed-state guard (RESEARCH §Idempotency Design). Required by SCALE-03 (verification of the "exactly one row" criterion is in plan 16-04).
Output: Core migration + entity property + EF config + idempotent write in `ProposalService.CreateSessionAsync`.
</objective>
