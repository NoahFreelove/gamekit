    **W9 — PRESCRIPTIVE antiforgery pattern (apply to ALL five dialogs):** `BanPlayerDialog`, `UnbanPlayerDialog`, `GdprDeleteDialog`, `DeleteAdminDialog`, `CreateAdminDialog`.

    1. Inject `IAntiforgery` + `IHttpContextAccessor` into the dialog component.
    2. On first render, capture the token via `GetAndStoreTokens`.
    3. On submit, send the header with `AdminAuthenticationSchemeConstants.CsrfHeaderName` as the key and `tokens.RequestToken` as the value.

    The canonical Razor snippet (copy verbatim — all five dialogs follow the same shape):

    ```razor
    @inject HttpClient Http
    @inject Microsoft.AspNetCore.Antiforgery.IAntiforgery Antiforgery
    @inject Microsoft.AspNetCore.Http.IHttpContextAccessor HttpContextAccessor

    @code {
        private Microsoft.AspNetCore.Antiforgery.AntiforgeryTokenSet? _tokens;

        protected override void OnInitialized()
        {
            var ctx = HttpContextAccessor.HttpContext
                ?? throw new InvalidOperationException("No HttpContext — dialog must render within a Blazor Server request.");
            _tokens = Antiforgery.GetAndStoreTokens(ctx);
        }

        private async Task SubmitAsync()
        {
            // Reason + request DTO bind via MudForm; client-side validation has already passed.
            Http.DefaultRequestHeaders.Remove(AdminAuthenticationSchemeConstants.CsrfHeaderName);
            Http.DefaultRequestHeaders.Add(
                AdminAuthenticationSchemeConstants.CsrfHeaderName,
                _tokens!.RequestToken);

            var resp = await Http.PostAsJsonAsync(
                $"/admin/api/players/{PlayerId}/ban",
                new BanPlayerRequest(_reason));
            // Handle resp.StatusCode: 200 closes dialog, 400 renders ValidationProblem, 403/404 show error alert.
        }
    }
    ```

    Reasoning: Blazor Server's `EditForm` auto-antiforgery is specifically for server-rendered `<form>` POSTs — it does NOT cover the `HttpClient` JSON-POST flow the admin dialogs use to hit `/admin/api/*`. Injecting `IAntiforgery` + echoing the token in the header is the deterministic path.

    Apply the same pattern (swap the POST URL + request DTO) to `UnbanPlayerDialog` (POST `/admin/api/players/{id}/unban`), `GdprDeleteDialog` (POST `/admin/api/players/{id}/gdpr-delete` — superadmin-only), `CreateAdminDialog` (POST `/admin/api/admins`), and `DeleteAdminDialog` (DELETE `/admin/api/admins/{id}` — use `Http.SendAsync(new HttpRequestMessage(HttpMethod.Delete, url) { ... })` with the same CSRF header on the request).

    NOTE: GET `/admin/api/players/search` (W8) does NOT need the CSRF header since it is read-only.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin (browser) → Blazor Server circuit | SignalR-backed; Blazor's default output encoding blocks XSS on `@variable` binds. |
| admin form submission → /admin/api/* | Antiforgery token + admin cookie required. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09-01 | Tampering | XSS via ban reason rendered in audit log | mitigate | Blazor default HTML-encodes `@auditRow.Reason`. Audit.razor does NOT use `MarkupString`. Reviewer confirms zero `MarkupString` usages in this plan. |
| T-03-09-02 | Elevation of Privilege | Non-superadmin accesses Admins page via direct URL | mitigate | Page `[Authorize(Policy = AdminPolicies.Superadmin)]` gates at the route level; cookie events render 403 on mismatch. |
| T-03-09-03 | Information Disclosure | Dialog state persists across sessions | accept | Blazor Server per-circuit scope; state dies with circuit on logout/refresh. |
| T-03-09-04 | Tampering | Reflection-loaded IMatchmakingStrategy bypasses policy | mitigate | Reflection only queries for type existence; no call path. Page displays data only after explicit Phase 5 plan ships the interface. |
| T-03-09-05 | Information Disclosure | Missing-package alert leaks internal service names | accept | Message strings are intentionally operator-facing. No secrets. |
| T-03-09-06 | Tampering | Ban dialog submits without CSRF | mitigate | Antiforgery token required by backend filter (plan 03-07); EditForm auto-includes the token via Blazor Server convention. |
</threat_model>
