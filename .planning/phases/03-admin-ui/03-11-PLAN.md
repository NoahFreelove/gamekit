<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI input → Postgres via gamekit_owner | Fully trusted; CLI assumes the operator has shell access + connection-string authority. |
| password prompt → stdout/stderr | Must NOT echo to terminal (avoids shell history + terminal scrollback leakage). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-11-01 | Information Disclosure | Password echoes to terminal / shell history | mitigate | `Console.ReadKey(intercept: true)` loop — only `*` characters printed. Flag-based path still risks shell history; documented guidance says `--password` via shell history is operator's responsibility. Env var path (`GAMEKIT_ADMIN_PASSWORD`) is the CI-friendly alternative. |
| T-03-11-02 | Elevation of Privilege | Adversary runs `admin create` on empty DB to seize superadmin role | accept | CLI access presupposes filesystem + DB connection access; the adversary already owns the host. This is the BOOTSTRAP path, not an attack surface. |
| T-03-11-03 | Tampering | CLI creates admin with role = 'root' (bypasses CHECK) | mitigate | Validator enforces `--role admin|superadmin`; Postgres CHECK constraint `ck_admin_users_role` is final gate. |
| T-03-11-04 | Denial of Service | Duplicate username race under concurrent CLI invocations | mitigate | EF unique-index 23505 surfaces as `UsernameAlreadyExists` exception → exit code 2. No silent corruption. |
| T-03-11-05 | Information Disclosure | Error messages leak Postgres connection-string | mitigate | Error handler prints only message text (not full exception); password + connection string are never echoed. |
</threat_model>
