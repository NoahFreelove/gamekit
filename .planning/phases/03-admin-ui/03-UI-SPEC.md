# Phase 03 — UI Design Contract (GameKit Admin Console)

> Visual and interaction contract for Phase 3: Admin UI (Blazor Server). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Aesthetic target:** Sentry admin / Linear settings / pgAdmin / Portainer — an operator-facing internal tool, not a consumer dashboard. Data-dense, neutral, keyboard-friendly.
>
> **Route scope note (revision 2026-04-18):** all routes in this spec (e.g. `/admin/login`, `/admin/players`, `/admin/audit`) are Blazor Server Razor-page routes declared via `@page` directives. They are **fixed at `/admin/*`** regardless of `GameKitAdminOptions.MountPath`. `MountPath` scopes only the admin HTTP API prefix (`/admin/api/*`); the Blazor shell is mounted by the framework via `MapRazorComponents<App>()` and MudBlazor static assets (`_content/MudBlazor/*`) are root-relative. Dynamic Blazor-route rewriting is out of scope for v1 (flagged as potential v2 feature).

## Spacing Scale

Declared values — all multiples of 4. Bound to MudBlazor's 4px base (MudBlazor's `Spacing = 4` default matches this). Expose as CSS custom properties on `.gk-admin-root` so consumer CSS isolation can reference them.

| Token | Value | CSS var | MudBlazor unit | Usage |
|-------|-------|---------|----------------|-------|
| `xs` | 4px | `--gk-space-1` | Spacing="1" | Icon gaps, chip inner padding |
| `sm` | 8px | `--gk-space-2` | Spacing="2" | Form field gap, compact table cell padding |
| `md` | 16px | `--gk-space-4` | Spacing="4" | Default card padding, sidebar section gap |
| `lg` | 24px | `--gk-space-6` | Spacing="6" | Content-area outer padding, panel-to-panel gap |
| `xl` | 32px | `--gk-space-8` | Spacing="8" | Dashboard grid gutter |
| `2xl` | 48px | `--gk-space-12` | Spacing="12" | Major section break (e.g. Login page form → footer stub) |
| `3xl` | 64px | `--gk-space-16` | Spacing="16" | Empty-state vertical padding |

**Exceptions:**

- **Focus ring:** 2px offset (not on the 4px grid, but standard for accessibility). `outline: 2px solid var(--gk-color-focus); outline-offset: 2px;` globally.
- **Table row height:** **40px** (data-dense compact density, per brand hints). Row padding reduces to `sm` (8px) vertical.
- **Top nav bar height:** **56px** fixed.
- **Sidebar width:** **240px** expanded, **64px** icon-rail collapsed.

## Typography

System font stack resolves to SF Pro on macOS, Segoe UI on Windows, Roboto on Android, Ubuntu on Linux — native feel on every operator workstation, zero network fetch, zero license concern.

**Declared sizes (exactly 4):** 12, 14, 16, 20 px.
**Declared weights (exactly 2):** 400 (regular) + 600 (semibold).

| Role | Size | Weight | Line Height | Used For |
|------|------|--------|-------------|----------|
| Caption | 12px | 400 | 1.4 (17px) | Table metadata (timestamps, chip text, help text under inputs) |
| Body | 14px | 400 | 1.5 (21px) | Default body, form inputs, table cell content |
| Label | 14px | 600 | 1.4 (20px) | Form labels, nav item text, small section titles, badges |
| Heading | 20px | 600 | 1.3 (26px) | Panel titles, page titles ("Player search", "Audit log") |

**Monospace exceptions (mono stack, same sizes):**

- Player IDs (UUIDs): `caption` or `body` mono.
- Timestamps in tables: `caption` mono.
- JSON diffs in audit log: `caption` mono in a scrollable `<pre>` block.
- CLI command hints (first-admin missing state): `body` mono inside a `<code>` inline tag.

**Display:** not declared — no marketing-scale text anywhere in admin.

**Rules:**

- Heading-to-body contrast is weight + color (labels vs. body), not size. Keeps the operator tool dense.
- Line-height 1.5 on body (per WCAG 1.4.8 readability guidance); 1.3 on heading (tight for data density).
- Tabular numerals enabled on all tables via `font-variant-numeric: tabular-nums` (IDs and numeric columns align).

## Color

**60 / 30 / 10 split** — 60% dominant neutral surface, 30% secondary structural (cards/sidebar/nav), 10% accent (primary actions + active states only).

**Token naming convention:** `--gk-color-{semantic}-{shade}`. Semantic tokens map to raw palette via CSS custom properties on `.gk-admin-root`, which gives us a future dark-mode hook (CONTEXT deferred).

### Neutral palette (60% + 30%)

| Token | Hex | Usage |
|-------|-----|-------|
| `--gk-color-bg` (60%) | `#F8FAFC` (slate-50) | Page background, content area |
| `--gk-color-surface` (30%) | `#FFFFFF` | Cards, sidebar, top nav, dialogs, panels |
| `--gk-color-surface-alt` (30%) | `#F1F5F9` (slate-100) | Table header row, hover row, inline code bg |
| `--gk-color-border` | `#E2E8F0` (slate-200) | Card border, table divider, input border |
| `--gk-color-text-primary` | `#0F172A` (slate-900) | Default body text, headings |
| `--gk-color-text-secondary` | `#475569` (slate-600) | Captions, helper text, timestamps |
| `--gk-color-text-disabled` | `#94A3B8` (slate-400) | Disabled inputs, placeholder text |

### Accent (10%)

| Token | Hex | Usage |
|-------|-----|-------|
| `--gk-color-primary` | **`#4263EB`** (indigo-600) | Primary CTA buttons, active nav item, focused input border, focus ring |
| `--gk-color-primary-hover` | `#364FC7` (indigo-700) | Primary CTA hover |
| `--gk-color-primary-subtle` | `#EDF2FF` (indigo-50) | Active nav item background, selected row left-border |

**Accent reserved for — explicit allowlist:**

1. Primary CTA button on any given page (exactly **one** per view): Sign in, Confirm Ban, Create admin, Adjust rating, Save, Load more.
2. Active sidebar item (background `primary-subtle`, left-border `primary`, text `primary`).
3. Focused form control border + 2px focus ring.
4. Links inside body copy (underline on hover).
5. Active tab indicator (if tabs used within a panel — e.g. Player detail sub-nav).

**Accent is NEVER used for:** secondary buttons, icons-as-decoration, chart fills, success/info states (use semantic tokens below), borders on non-focused inputs, header background.

### Semantic status palette

| Token | Hex | Usage | Chip label |
|-------|-----|-------|-----------|
| `--gk-color-success` | `#16A34A` (green-600) | Health panel: "OK" status chip, unban-success toast, rating-increase delta | "Healthy" / "Online" |
| `--gk-color-success-subtle` | `#DCFCE7` (green-100) | Success chip background | — |
| `--gk-color-warning` | `#D97706` (amber-600) | Health panel: "Degraded" chip, non-blocking warning toasts, error-rate > threshold | "Degraded" |
| `--gk-color-warning-subtle` | `#FEF3C7` (amber-100) | Warning chip background | — |
| `--gk-color-info` | `#2563EB` (blue-600) | Missing-package placeholders (Rankings / Matchmaking absent), info toasts | "Info" |
| `--gk-color-info-subtle` | `#DBEAFE` (blue-100) | Info chip / placeholder card background | — |
| `--gk-color-danger` | **`#DC2626`** (red-600) | Destructive actions: Ban button, GDPR Delete button, error toasts, "Banned" player badge, Redis/Postgres offline status chip | "Banned" / "Offline" / "Error" |
| `--gk-color-danger-subtle` | `#FEE2E2` (red-100) | Destructive-confirm dialog accent strip, banned-row left border, error chip background | — |
| `--gk-color-focus` | `#4263EB` (same as primary) | Focus ring (2px outline) | — |

**Contrast check (WCAG AA target):**

- `text-primary` (`#0F172A`) on `bg` (`#F8FAFC`) → 17.6:1 (AAA).
- `text-primary` on `surface` (`#FFFFFF`) → 18.9:1 (AAA).
- `text-secondary` (`#475569`) on `surface` → 7.2:1 (AAA).
- `primary` (`#4263EB`) text on `surface` → 6.4:1 (AA large, AAA normal — acceptable).
- White text on `primary` button → 5.1:1 (AA).
- White text on `danger` button (`#DC2626`) → 4.8:1 (AA).

All combinations pass WCAG 2.1 AA for normal text. Declared baseline: **AA minimum everywhere; AAA where cost-free**.

## Layout Shell

The shell is fixed; the content area scrolls. Implemented as a single `MainLayout.razor` in `GameKit.Admin.UI/Layout/`, used for every non-login page.

### Top nav (56px fixed, `surface` bg, 1px bottom border `border`)

Left → right:

1. **Brand mark** (24px): "GameKit Admin" label (`label` weight + `primary` color) — links to `/admin` dashboard.
2. **Sidebar collapse toggle** (icon button, 40×40): toggles sidebar between 240px and 64px.
3. (flex spacer)
4. **Environment chip** (`caption` + `info-subtle` bg): `dev` / `staging` / `production` — read from `IHostEnvironment`. Hidden in Production (no need to remind ops of prod — and the absence itself signals prod).
5. **User menu** (avatar initial in 32px circle + username + role chip):
   - Role chip uses `primary-subtle` bg for `admin`, `danger-subtle` bg + `danger` text for `superadmin` (visual signal that this operator can do irreversible things).
   - Click opens `MudMenu` with: "Signed in as {username}", divider, "Log out" (danger-text).

### Sidebar (240px expanded, `surface` bg, 1px right border)

Persistent on desktop. Collapsible to 64px icon rail via the top-nav toggle (state persisted in a cookie `gk_admin_sidebar` so operators' choice survives reload).

Nav items (icon + label; label hidden when collapsed, icon shows tooltip):

1. **Dashboard** (`home` icon) — `/admin` — overview cards: health, queue-depth, recent audit log (top 5).
2. **Players** (`person_search` icon) — `/admin/players` — unified search + results list.
3. **Match history** (`history` icon) — `/admin/matches` — optional top-level match browser (same component also used inside player detail).
4. **Audit log** (`receipt_long` icon) — `/admin/audit` — full audit log with filters.
5. **Health** (`favorite` icon) — `/admin/health` — Postgres/Redis/error-rate panel.
6. **Queue depth** (`queue` icon) — `/admin/matchmaking` — Matchmaking panel or placeholder.
7. **Rank adjust** (`tune` icon; superadmin-only) — `/admin/rankings/adjust` — Rankings panel or placeholder.
8. Divider.
9. **Admins** (`admin_panel_settings` icon; superadmin-only) — `/admin/admins` — list + create/delete admin accounts.

Active item: `primary-subtle` background, `primary` left-border (3px), `primary` text. Hover on inactive: `surface-alt` background.

### Content area (fills remaining space; scrolls independently)

- Outer padding: `lg` (24px) on all sides.
- Inter-panel gap: `lg` (24px).
- Max content width: none (data-dense; full viewport used).

### Footer (not persistent; not rendered)

No footer. Keeps vertical space for data tables.

## Surface-by-Surface Contracts

Each surface below declares: route, purpose, layout, components, empty/loading/error copy, a11y + keyboard requirements, interaction contract.

### 1. Admin login page — `/admin/login`

- **Layout:** Centered card on blank `bg`, no shell. Card: 400px wide, `lg` padding, `surface` bg, 1px `border`, 8px radius, 1-level shadow.
- **Components (top→bottom):** "GameKit Admin" heading (20px/600) → 8px gap → "Sign in to continue" caption (12px/400/text-secondary) → 24px gap → `MudTextField` Username (autofocus, `autocomplete="username"`) → 16px gap → `MudTextField` Password (`type=password`, `autocomplete="current-password"`) → 8px gap → "Remember me for 30 days" `MudCheckBox` (label) → 24px gap → "Sign in" `MudButton` (Color=Primary, Variant=Filled, FullWidth) → 16px gap → "Forgot password? Contact a superadmin." small text (12px/text-secondary, centered).
- **Primary CTA copy:** **Sign in**
- **Errors:**
  - Invalid credentials → inline `MudAlert` Severity=Error above form: "Username or password is incorrect."
  - Rate limit (429) → inline `MudAlert` Severity=Warning: "Too many login attempts. Try again in a minute."
  - Account banned/disabled → inline `MudAlert` Severity=Error: "This account has been disabled. Contact a superadmin."
  - Network/server 5xx → inline `MudAlert` Severity=Error: "Sign in is unavailable right now. Retry in a moment."
- **Loading:** Button shows `MudProgressCircular Size=Small` + label text "Signing in…" — form disabled, no skeleton elsewhere.
- **a11y:** Form has `aria-label="Admin sign in"`. Each input has visible `<label>` + `for` linkage. Error alert uses `role="alert"` (auto-announced). Error messages referenced via `aria-describedby` on the input. Tab order: Username → Password → Remember → Sign in.
- **CSP:** No inline scripts on this page (no Blazor Server circuit until sign-in? — actually Blazor Server starts the circuit on this page; the `<script src="_framework/blazor.server.js" nonce>` is served with the per-request nonce per D-15).

### 2. First-admin-missing state (dev/staging only) — renders on `/admin/login` when zero superadmins exist

- **Layout:** Replaces the sign-in form inside the same card.
- **Copy (heading 20px/600):** "No admin configured yet"
- **Body (14px/400, secondary):** "No superadmin exists in this database. Bootstrap one from a terminal to sign in:"
- **Code block (mono 14px, `surface-alt` bg, 8px radius, `md` padding, select-all on click):**
  ```
  dotnet gamekit admin create
  ```
- **Footer line (12px/secondary):** "You'll be prompted for a username and password. The first admin is automatically promoted to superadmin."
- **Environment chip** above the heading: shows current env (`dev` or `staging`) in `info-subtle`. In `production` this state never renders — startup asserts fail-fast per CONTEXT D-04.
- **No interactive controls.** Operator must open a terminal.

### 3. Dashboard — `/admin`

- **Layout:** 12-column CSS grid inside content area, `lg` (24px) gutter. Cards span:
  - Row 1: Health (span 6) + Queue depth (span 6)
  - Row 2: Recent audit log (span 8) + Quick stats (span 4) — Quick stats: admin count, banned player count, sessions-completed-today
- **Cards:** `surface` bg, `md` padding, 1px `border`, 6px radius, no shadow.
- **Empty states:** Each card owns its empty state (see per-panel sections below).

### 4. Player search — `/admin/players`

- **Unified search box (top of page, sticky):** Full-width `MudTextField` with:
  - Placeholder: `Search by player id, display name, or provider:external_id`
  - Leading icon: `search`
  - Trailing icon (when typed): clear `close` button
  - Debounce: 250ms after keystroke before firing query
  - Below the box, a 12px/secondary helper line: `Examples: 0196e1a2-… | alice | steam:76561198012345678`
- **Empty (before search):**
  - Heading: `Search for a player`
  - Body: `Enter a player ID, display name, or provider:external_id above. Results appear here.`
  - Illustration: none (internal tool; skip decorative illustrations).
- **Empty (after search, zero hits):**
  - Heading: `No matches`
  - Body (text-secondary): `No player matched "{query}". Try a different spelling, a provider:external_id lookup, or a UUID.`
- **Results:** `MudDataGrid<PlayerSearchResult>` with columns:
  1. Player ID (mono caption; truncated to 8 chars + ellipsis; full value on hover tooltip; click → copy-to-clipboard)
  2. Display name (body)
  3. Primary identity (caption mono — e.g. `steam:76561…`)
  4. Created (caption mono — `2026-04-18 14:03 UTC`)
  5. Status — `Active` chip (success-subtle) or `Banned` chip (danger-subtle)
  6. Actions — `View` `MudButton` Variant=Text Size=Small → `/admin/players/{id}`
- **Row:** 40px compact. Click anywhere on row → same as View. Hover bg: `surface-alt`. Banned rows get a 3px `danger` left-border.
- **Pagination:** keyset — Load-more button below grid. Copy: `Load 50 more`. When no more: disables + label `End of results`.
- **Loading (first query):** Replace grid with 5 `MudSkeleton` rows (40px each) matching the column layout.
- **Loading (load-more):** Button spinner, existing rows remain.
- **Error:** `MudAlert Severity=Error` above grid: `Search failed. {problem}. Try again.` where {problem} is one of: "Network error", "Server returned 500", "You are no longer signed in" (→ redirect to login). Alert has a "Retry" button.

### 5. Player detail — `/admin/players/{id}`

- **Layout (top→bottom):**
  1. **Header card** (`surface`, `lg` padding): back arrow → `MudBreadcrumbs` `Players › {display_name}` + action buttons cluster (right-aligned): `Ban` (danger, if not banned) OR `Unban` (warning, if banned) + `Delete (GDPR)` (danger outline; **superadmin-only, hidden for admin role**).
  2. **Metadata row** (4 data pairs inline): ID (mono, click-to-copy), Created, Last seen, Role (n/a for players — show "Player").
  3. **Tabs** (`MudTabs`): Identities | Credentials | Match history | Rank (shows placeholder when Rankings absent).
  4. **Audit breadcrumb footer** (caption): `Last admin action: {action} by {actor_username} at {timestamp}` (if any; hide if zero).
- **Banned indicator:** If `is_banned`, header card gets a `danger-subtle` top border (3px) and a "Banned" chip next to display name + an inline "Reason: {ban_reason}" line (14px/secondary) with "Unban" button inline.
- **Identities tab:** `MudDataGrid` — provider | external_id (mono) | display_name | linked_at. Empty: `No linked identities.` Body: `This player has no external identity providers linked.`
- **Credentials tab:** card showing: Username (if set), Password updated (timestamp), Hash prefix (mono, first 8 chars + `…`), "(never display full hash)" caption. Empty: `No password credential set.` Body: `This player has never set a password (guest or OAuth-only).`
- **Match history tab:** `MudDataGrid<Match>` — columns: Session ID (mono cap), Ladder, Result (W/L/D chip), Rating before → after (mono + delta chip), Completed at. Keyset pagination. Empty: `No match history yet.` Body: `This player hasn't completed any matches.`
- **Rank tab:** If `GameKit.Rankings` registered, show rank table per ladder. Else, `MudAlert Severity=Info`: `Install GameKit.Rankings to view this player's rankings.` (see "Missing package placeholders" below).

### 6. Ban confirmation dialog

- **Trigger:** `Ban` button on player detail.
- **Dialog (`MudDialog`, MaxWidth=Small):**
  - **Title (20px/600):** `Ban {display_name}?`
  - **Body:** Top-stripe `danger-subtle` 4px — then paragraph (14px/secondary): `Banned players cannot sign in. Existing sessions self-expire within 15 minutes. This action writes an entry to the admin audit log. You can unban later.`
  - **Reason field (required):** `MudTextField` multiline, 3 rows, `Label=Reason (visible to admins only)`, `Placeholder=e.g. Chat harassment in session 0196…` — helper text (caption): `3–512 characters. Stored verbatim in the audit log.`
  - Validation errors inline (red underline + helper text below field):
    - < 3 chars: `Reason must be at least 3 characters.`
    - > 512 chars: `Reason is too long (max 512 characters).`
    - Empty on submit: `A reason is required.`
  - **Buttons (right-aligned, bottom):** `Cancel` (Variant=Text) + `Ban player` (Variant=Filled, Color=Error).
- **Submitting state:** `Ban player` button shows spinner + label `Banning…`; both buttons disabled; reason field read-only.
- **Success:** Dialog closes. `ISnackbar` toast Severity=Success: `Player {display_name} banned.` Player detail refreshes to show banned state.
- **Error:** Inline `MudAlert Severity=Error` above buttons: `Ban failed: {reason}. Try again.` Retryable.
- **a11y:** Dialog is `role=dialog` (MudBlazor default) with `aria-labelledby` pointing at title. Focus moves to reason field on open. Esc = Cancel. Enter in reason field = submit (unless Shift+Enter for newline).

### 7. Unban confirmation dialog

- Same shape as Ban dialog, reason field optional (caption: `Optional — documents why the ban is being lifted.`).
- **Primary button:** `Unban player` (Variant=Filled, Color=Warning) — warning, not error, because unban is reversible and less destructive.
- **Success toast:** `Player {display_name} unbanned.`

### 8. GDPR delete confirmation — superadmin-only

- **Trigger:** `Delete (GDPR)` button on player detail. Button has tooltip `Permanent player deletion. Superadmin only.`
- **Dialog (MaxWidth=Small; two-step confirmation):**
  - **Title:** `Delete {display_name} permanently?`
  - Top-stripe `danger` (4px, solid — stronger than the ban stripe).
  - **Body (14px):** `This is irreversible. The player's profile, identities, password credential, and session participation records will be anonymized or removed. Opponent foreign keys will be set to NULL. Rating history becomes unattributable. The admin audit log entry for this action is retained.`
  - **Confirmation step 1:** `MudTextField` — `Label=Type "{display_name}" to confirm` — disable the delete button until the typed value matches exactly (case-sensitive).
  - **Buttons:** `Cancel` + `Delete player` (Variant=Filled, Color=Error, disabled until text match).
- **Success toast:** `Player {display_name} deleted. Audit log updated.` Redirect to `/admin/players`.
- **Error inline:** `Delete failed: {reason}. The database was not changed. Try again or contact another superadmin.`

### 9. Audit log — `/admin/audit`

- **Filters (top row, `MudPaper` 1px border, `md` padding):**
  - Action namespace `MudSelect<string>`: (All) / admin.player.ban / admin.player.unban / admin.player.gdpr_delete / admin.player.rank_adjust / admin.admin.create / admin.admin.delete / admin.signing_key.rotate
  - Actor `MudTextField`: username prefix filter
  - `Apply filters` `MudButton` (Variant=Text) + `Reset` link
- **Grid (`MudDataGrid<AuditEntry>`, keyset-paginated):**
  - Columns: Timestamp (mono cap) | Actor (body) | Action (code chip, `caption` mono, `surface-alt` bg) | Target (mono cap, truncated) | Expand (icon button `expand_more`)

### 10. Health panel — `/admin/health` (and dashboard card)

- **Layout:** 3 status tiles in a row (flex, `md` gap). Each tile: 1px `border`, `surface` bg, `md` padding, 4px radius.

  - Line 3: `caption` (12px/secondary) — latency or error-count detail, e.g. `ping 2.1 ms` or `3 errors / last 5 min`.
  - Line 4: `caption mono` (12px) — last-checked timestamp, e.g. `updated 14:03:22 UTC`.
- **Status mapping:**
  - `OK` — success color, icon `check_circle`
  - `Degraded` — warning color, icon `warning`
  - `Down` / `Error` — danger color, icon `error`
- **Refresh controls (top-right of panel, single row):**

- **Loading (first load):** All three tiles show `MudSkeleton` sized to match.
- **Error fetching status:** Tile shows `Down` state + caption `Unable to contact Postgres.` Refresh button remains enabled.

**Voice rules:**

- Second person (`you`) is OK but sparse — the operator is talking to an internal tool, not being coached.
- Imperative mood for actions (`Sign in`, `Ban player`, `Adjust rating`) — no `Please` / `Click to` / `Would you like to`.
- Data labels are nouns (`Reason`, `Username`, `Role`) — not sentences.
- Error messages state the problem first, then the path forward: `{Action} failed: {reason}. Try again.` Never `Oops!` / `Something went wrong.`
- Timestamps always include `UTC` explicitly, mono font, ISO-ish format (`2026-04-18 14:03:22 UTC`).
- Code references (CLI commands, action namespaces) in mono font, inline `<code>` or `<pre>`.

## Interaction Contract — keyboard & focus

| Control | Keyboard behavior |
|---------|-------------------|
| Tab order (any form) | Left-to-right, top-to-bottom, skipping disabled controls. |
| Enter in text field | Submit enclosing form (except multiline reason fields, where Shift+Enter is newline and Enter is submit). |

| Sidebar nav | Arrow Up/Down between items; Enter activates. |
| Data grid row | Arrow Up/Down between rows; Enter = "View" action. |

**Focus management on route change:** On Blazor navigation, move focus to the page's `<h1>` (page title) so screenreader users hear the page change.

**aria:** All MudBlazor components ship correct aria. Custom markup (status chips, JSON diff `<pre>` blocks, empty-state panels) must set:

- Status chips: `role="status"` + `aria-label="{status text}"` for non-text-chip variants.
- Icon-only buttons: `aria-label="{verb}"`.
- Expandable audit rows: `aria-expanded="true|false"` on the expand button.
- Alerts with auto-hide: `role="status"` (polite). Errors that require acknowledgement: `role="alert"` (assertive).

## Asset Loading & CSP Discipline

- **No CDN references.** Fonts are system stack; MudBlazor CSS is bundled static asset served from `_content/MudBlazor/`; Material Symbols icons ship embedded in MudBlazor 9.3.0 (verify during Phase 3 execution — fallback is to vendor them as a static asset).
- **Per-request nonce** on every `<script>` tag in the admin layout (CONTEXT D-15). The Blazor Server framework script (`_framework/blazor.server.js`) gets the nonce from the HTTP context via a `ComponentRenderMode` attribute or a custom `App.razor` head outlet.
- **`style-src 'self' 'unsafe-inline'`** is accepted (CONTEXT D-15) because MudBlazor renders inline styles for dynamic values. Non-MudBlazor inline styles should be moved to `*.razor.css` scoped files wherever practical.
- **`frame-ancestors 'none'`** — admin cannot be framed. No iframe embeds anywhere.
- **No external image URLs.** Player avatar URLs from Steam/Discord identity metadata are allowed only if `img-src 'self' data: https://*.steamstatic.com https://cdn.discordapp.com` is added — executor decides during implementation. Default: we do NOT display avatar images in v1 (avoids the CSP expansion + external-fetch concern). Show the player's display name + a color-block letter-avatar instead.
