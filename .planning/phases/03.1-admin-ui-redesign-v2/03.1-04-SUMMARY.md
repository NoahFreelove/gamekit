## Decisions Made

1. **DTO drops `RequiresSuperadmin` from the wire format** — D-11 says "never grayed, always absent." That principle extends to the JSON: not just hidden rows, but no flag in the response that could betray the existence of hidden rows. The DTO is intentionally narrower than the in-process record.
2. **SSR mirror of the endpoint filter** — `CommandPalette.OnInitializedAsync` projects `AdminCommandRegistry.AllCommands` through the same filter as `GetCommandsAsync`. Operator opens Cmd+K, palette is already populated; no fetch round-trip on the first open. The endpoint exists for the Plan 03 JS to refresh on demand and as the documented public contract.
3. **Plain HTML `onclick` on the TopNav button** — `@onclick` would require a SignalR roundtrip to dispatch; we want zero-latency UX for keyboard openers. The `window.GKAdmin && …` guard makes it safe if the bundle failed to load.
4. **18 entries, including some awkward navs** — the plan asks for "10 nav rows for each existing `/admin/*` @page route." There are exactly 10 such routes (Dashboard / Players / PlayerDetail / Audit / Health / Matches / QueueDepth / RankAdjust / Admins / Login). Two are awkward as palette navs (PlayerDetail is parameterized; Login is a sign-out alternative) — the JS dispatches to MainLayout.OpenDialog which silently no-ops on unknown command IDs, so an awkward nav is a no-op rather than a bug.

## OpenDialog bridge — palette dispatch confirmation

Plan 03's `MainLayout.OpenDialog([JSInvokable])` switch routes the following `commandId` values: `ban`, `unban`, `gdpr-delete`, `create-admin`, `delete-admin` (5 wired). The registry in this plan exposes those plus `rank-adjust`, `rotate-signing-key`, `sign-out` (8 actions) + 10 nav rows. JS dispatch path:

1. Operator presses Cmd+K → `gamekit-admin.js` `openPalette()` → `<html data-palette-open="true">` → CSS shows `.palette-scrim`.
2. Palette already pre-rendered with role-filtered rows (no fetch needed for first open).
3. Operator types "ban" → `_filterPalette` narrows rows by `data-label` substring.
4. Operator presses Enter → `_activateSelection()` clicks the selected row → click handler reads `data-command-id="ban"` and `data-requires-target="true"` → enters target-pick state.
5. Operator types "alice" → `fetch('/admin/api/players/search?query=alice')` (already shipped by Phase 03, idempotent GET, no antiforgery).
6. Operator selects the player → `_dispatchOpenDialog("ban", playerId, "alice")` → `_dotNetRef.invokeMethodAsync('OpenDialog', "ban", playerId, "alice")` → `MainLayout.OpenDialog` switch dispatches `BanPlayerDialog` via `IDialogService`.

The bridge is dispatched at least once per ban / unban / gdpr-delete / create-admin / delete-admin invocation through the palette — confirmed by reading the Plan 03 `gamekit-admin.js` event flow against this plan's markup contract (selectors verified verbatim against the JS reads).
