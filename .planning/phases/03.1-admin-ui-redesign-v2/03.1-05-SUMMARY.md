## Decisions Made

1. **Markup-only Razor component.** Plan 03's `gamekit-admin.js` is the single source of truth for tweaks state — it reads/writes `localStorage 'gamekit.admin.tweaks'`, applies `data-*` attrs on `<html>`, handles open/close, owns reset semantics. Adding any `@code { }` state in Razor would risk drift between the Blazor view-model and the JS state. The component is a pure DOM contract surface (selectors).
2. **Singleton at layout root.** Mirrors the Plan 04 `CommandPalette` discipline — overlay components live adjacent in `MainLayout` so the CSS visibility flip on `<html data-tweaks-open=true>` works regardless of which `/admin/*` page is currently rendered.
3. **`IJSRuntime.InvokeVoidAsync` instead of plain-HTML onclick.** The `MudIconButton.OnClick` parameter takes a `EventCallback`, so `OnClick="@(() => JS.InvokeVoidAsync(...))"` is the idiomatic path. Yes, this incurs a SignalR roundtrip — but the Tweaks button is a low-frequency trigger (operators open it occasionally, not per-keystroke). Cmd+K (which is high-frequency) earned the plain-HTML `onclick` shortcut in Plan 04; Tweaks doesn't need it.
4. **D-08 graceful-degrade buttons sit inside the same radiogroup.** Sketch fidelity: the dashboard-direction picker is a 4-option group (D + A/B/C). Per ARIA spec, all 4 should sit in the same `role="radiogroup"`. Disabling A/B/C with `disabled aria-disabled="true" title="coming soon"` is the standard pattern for "feature shape preserved; affordance temporarily unavailable."
5. **Scoped CSS does NOT redeclare `.tweaks-scrim { display: none }`.** The plan template included that rule with a comment claiming a global flip exists — the global flip targets `.tweaks-panel`, not `.tweaks-scrim`. Adding `display: none` on the scrim would hide its only child (the panel) regardless of the global flip, breaking the open state. See deviation #1.

## Tweaks state contract — operator round-trip

The 5-toggle contract surface this plan ships, paired with Plan 03's `gamekit-admin.js`:

1. Operator clicks Tune button in TopNav → `JS.InvokeVoidAsync("GKAdmin.openTweaks")` → `<html>` gets `data-tweaks-open="true"` → CSS `[data-tweaks-open="true"] .tweaks-panel { display: flex; }` reveals the panel inside the scrim wrapper.
2. Operator clicks `<button data-tweak="accent" data-value="indigo">` → delegated handler at `gamekit-admin.js:166-176` reads the two attrs → `saveTweaks({ accent: "indigo" })` → localStorage write + `applyAttrs` updates `<html data-accent="indigo">` → CSS accent ramp swap.
3. Operator clicks reset button (`data-tweak-action="reset"`) → handler at `gamekit-admin.js:178-179` → `resetTweaks()` clears localStorage + applies DEFAULTS (`{ accent: 'violet', density: 'compact', sidebar: 'expanded', banLoud: 'medium', dashDir: 'D' }`).
4. Operator presses Esc OR clicks outside the panel (`e.target === document.querySelector('.tweaks-scrim')`) OR clicks the close button (`onclick="window.GKAdmin && window.GKAdmin.closeTweaks()"`) → `<html>` loses `data-tweaks-open` → CSS hides panel.
5. On next page load, the inline `<script nonce="@Nonce">` in `App.razor` `<head>` (Plan 02) reads localStorage and applies the persisted attrs BEFORE `<body>` paints → no FOUC of default values.

D-08 graceful degrade verification: the dashDir A/B/C buttons render `disabled aria-disabled="true" title="coming soon"` and have NO `data-tweak` attribute, so the delegated click handler's `closest('[data-tweak]')` returns `null` for clicks on them — they are inert. Only the D button has `data-tweak="dashDir" data-value="D"` and dispatches.
