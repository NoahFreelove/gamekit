<objective>
Land the master-detail Players workspace — the second showpiece feature of this redesign.
The current Phase 03 implementation has two cooperating pages (`PlayerSearch.razor` for the
list + `PlayerDetail.razor` for the detail). This plan merges them into a single
`Players.razor` with two `@page` directives so the URL `/admin/players/{id}` is the source
of truth for both panes' state. The right-pane content is extracted into a shared
`PlayerDetailPane.razor` so the master-detail page can wrap it cleanly.

The medium ban banner (D-07 default) replaces the current `gk-player-banned-row` chip
inside the detail header. Banner shape responds to `[data-ban-loud]` on `<html>` (set by
the Tweaks panel via Plan 03's JS bundle); the Razor component is uniform — only the CSS
changes when the operator picks subtle / medium / loud.

**Purpose:** D-02 mandates master-detail; UI-SPEC §5.6 codifies the layout; D-07 ships
the medium ban banner default. ADMIN-05 and ADMIN-06 are re-verified post-redesign without
changing the underlying services.

**Output:** `Players.razor` (replaces 2 files), `PlayerDetailPane.razor` (extracted body),
`BanBanner.razor` (3-loudness banner), 2 live bUnit tests.
</objective>
