## Decisions Made

**Decision 1: Approach A (Url on AdminCommand) for GAP-1, not Approach B (separate Navigate JSInvokable)**

Approach A keeps the JS dispatch surface narrower. The URL is co-located with the command definition in the registry constants table rather than duplicated in a JS lookup table that would need to stay in sync. The bUnit test `Palette_RendersDataUrlOnNavRows` proves the Url flows all the way through server rendering to the DOM attribute the JS reads. Approach B (a `[JSInvokable] Navigate(string url)` on MainLayout) would add a second bridge contract with no correctness benefit.

**Decision 2: Approach B (string targetId at C# boundary) for GAP-3**

The plan specified both JS-side Guid.Empty fallback (in `_dispatchOpenDialog`) and C#-side string acceptance with `Guid.TryParse`. Both were implemented as defense in depth: the JS fix addresses the immediate failure; the C# fix prevents regression if the JS is ever rolled back or if other JS callers invoke OpenDialog with an empty string. The two fixes together implement the belt-and-suspenders pattern the plan called out.

**Decision 3: GKAdminConfig.apiBase in the existing nonce'd inline script block**

Extending the existing `<script nonce="@Nonce">` block (rather than adding a new script tag) avoids expanding the CSP surface and keeps all server-side bootstrap in one place. The `TrimEnd('/')` guard on MountPath prevents double-slash fetch URLs when consumers configure a trailing slash.
