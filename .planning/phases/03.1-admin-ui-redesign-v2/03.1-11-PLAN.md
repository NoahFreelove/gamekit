**Step 2.1 — Extend applyAttrs to reflect aria-checked on the matching button** (closes WARNING-01):

In `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js`, locate the existing `function applyAttrs(t)` at lines 72-77. Extend its body — preserve the existing `<html>` attribute write loop verbatim, then add the aria-checked reflection loop:

```javascript
  function applyAttrs(t) {
    var html = document.documentElement;
    Object.keys(ATTR_MAP).forEach(function (k) {
      html.setAttribute(ATTR_MAP[k], t[k] || DEFAULTS[k]);
    });
    // Phase 03.1-11 gap closure (WARNING-01): reflect the active option in each Tweaks
    // radiogroup so the existing CSS rule `.tweaks-options button[aria-checked='true']`
    // can style it AND so screen readers announce the selection. Iterates every
    // [data-tweak][data-value] button in the document and toggles aria-checked based on
    // the current tweak value. Idempotent — safe to call on every saveTweaks roundtrip.
    var optionButtons = document.querySelectorAll('button[data-tweak][data-value]');
    for (var i = 0; i < optionButtons.length; i++) {
      var ob  = optionButtons[i];
      var k   = ob.getAttribute('data-tweak');
      var v   = ob.getAttribute('data-value');
      var cur = t[k] || DEFAULTS[k];
      ob.setAttribute('aria-checked', cur === v ? 'true' : 'false');
    }
  }
```

Why iterate the DOM rather than building a static map: the Tweaks panel renders per server-render lifecycle (markup-only Razor), so the buttons exist whenever the bundle runs. The bundle's existing `applyAttrs(loadTweaks())` at line ~375 (the very last meaningful line before the public-API export) is the first call site — it runs at IIFE bottom, after the panel is server-rendered into the page. Subsequent calls happen on every saveTweaks round-trip (line 64 inside saveTweaks). No new call sites required; the existing ones already cover the lifecycle.
