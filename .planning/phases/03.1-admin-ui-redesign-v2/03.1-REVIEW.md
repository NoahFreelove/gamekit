# Phase 03.1: Code Review Report

**Reviewed:** 2026-05-01
**Depth:** deep (cross-file: JS interop ↔ Blazor bridge, JS fetch ↔ minimal-API contract, CSP middleware ↔ Razor markup)
**Status:** dirty (4 blockers, 9 warnings, 6 info)

## Summary

The redesign successfully ports the sketch CSS verbatim, preserves the
`Install GameKit.{PackageName}` load-bearing literal in `MissingPackageAlert`,
honors `D-11` server-side filtering on `GET /admin/api/commands`, and writes
no inline `style=` blocks that would require `style-src 'unsafe-inline'`. XSS
discipline holds (no `MarkupString`, no `innerHTML`, every dynamic value
flows through Razor `@`-encoding or `textContent`).

However the showpiece interactive surfaces (Cmd+K palette + Tweaks panel
opener) are wired via raw HTML `onclick=` attributes which the existing
strict CSP (`script-src 'self' 'nonce-…'`) **blocks at the browser** — the
Tweaks button never opens, the palette mouse-opener never opens, and only
the Cmd+K keydown path remains functional. Two further blockers in
`gamekit-admin.js` cripple the verb-engine flow that the redesign exists
to deliver: the two-step target search reads the wrong response shape
(`Array.isArray` is false against `{ items: [], hasMore: … }`), and
target-less actions dispatch `OpenDialog(commandId, "", "")` which fails
JSON→Guid deserialization on the .NET side. The CSP issue alone reduces
the Tweaks panel from "drawer with 5 toggles" to "no entry point";
combined with the broken verb-engine the redesign's headline UX features
ship inert.

The remaining warnings/info are quality issues — dead `IDisposable`
implementations, an `async void` LocationChanged handler, a
`nav.player-detail` palette row whose dispatch path doesn't exist,
hard-coded `/admin/api/players/search` that ignores `MountPath`, and
missing `aria-checked` toggling that breaks Tweaks selection visuals.

## Blockers

### BLOCKER-01: Inline `onclick=` HTML attributes are CSP-blocked — Tweaks drawer + palette mouse-opener are dead

**Files:**
- `src/GameKit.Admin.UI/Components/Layout/TopNav.razor:29`
- `src/GameKit.Admin.UI/Components/Shared/TweaksPanel.razor:26`

**Issue:** `AdminCspNonceMiddleware.cs:78` emits a strict
`script-src 'self' 'nonce-{nonce}'` directive with **no** `'unsafe-inline'`
and **no** `'unsafe-hashes'`. Per CSP Level 2/3 the absence of
`'unsafe-inline'`/`'unsafe-hashes'` from `script-src` blocks all inline
event handler attributes (including `onclick="…"`) — only nonced
`<script>` blocks and external `'self'` scripts execute. Both files write
raw HTML `onclick=` strings:

```razor
@* TopNav.razor:26-32 *@
<button type="button"
        class="search-trigger"
        aria-label="Search commands (Cmd+K)"
        onclick="window.GKAdmin && window.GKAdmin.openPalette()">
    <span class="placeholder">Search…</span>
    <kbd>⌘K</kbd>
</button>

@* TweaksPanel.razor:24-26 *@
<button type="button" class="tweaks-close"
        aria-label="Close tweaks"
        onclick="window.GKAdmin && window.GKAdmin.closeTweaks()">×</button>
```

The browser silently refuses to execute either handler and emits a
`Refused to execute inline event handler because it violates the
following Content Security Policy directive` console error. Operator
impact: the only documented path to the Tweaks drawer is the Tune button
in TopNav (`OnClick="@(() => JS.InvokeVoidAsync("GKAdmin.openTweaks"))"`,
which works) — but once the drawer is open, the close × button is dead;
the user must press `Esc` (which the keydown listener handles). The
search-trigger fake-input at the top is also dead for mouse users; only
the global `Cmd+K` keydown path opens the palette. The TweaksPanel
contradicts CONTEXT D-15 (`strict CSP with per-request nonce`) which
this phase explicitly claims to preserve.

**Fix:** Convert both to `@onclick` with C# event handlers (server-rendered
Blazor handlers are not subject to inline-event CSP), OR delegate the
clicks to the existing `gamekit-admin.js` click delegator. Option A
(preferred — matches the rest of the codebase):

```razor
@* TopNav.razor — replace the raw onclick with a JS interop call *@
<MudIconButton Icon="@Icons.Material.Filled.Search"
               Color="Color.Default"
               aria-label="Search commands (Cmd+K)"
               OnClick="@(() => JS.InvokeVoidAsync("GKAdmin.openPalette"))" />

@* TweaksPanel.razor close button — add a delegated data-action attribute *@
<button type="button" class="tweaks-close"
        aria-label="Close tweaks"
        data-tweaks-action="close">×</button>
```

Then in `gamekit-admin.js`, add to the existing global click delegator:

```javascript
// alongside data-tweak-action="reset"
var closeBtn = e.target && e.target.closest && e.target.closest('[data-tweaks-action="close"]');
if (closeBtn) { closeTweaks(); return; }
```

### BLOCKER-02: Two-step target search reads the wrong JSON shape — palette never returns matches

**File:** `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js:306-322`

**Issue:** The target-pick subview fetches from
`/admin/api/players/search?query=…`, then renders the response with:

```javascript
.then(function (r) { return r.ok ? r.json() : []; })
.then(_renderTargetResults)
…
function _renderTargetResults(rows) {
  …
  if (!Array.isArray(rows) || rows.length === 0) { … return; }
  …
  rows.forEach(function (p) { … btn.setAttribute('data-target-id', p.id || ''); … });
}
```

The endpoint actually returns
`PaginatedResult<PlayerRow>` —
`{ items: [...], nextCursor: string|null, hasMore: bool }` — see
`src/GameKit.Admin.UI/Http/AdminEndpoints.cs:217-226` and
`src/GameKit.Admin.UI/Http/Contracts/PaginatedResult.cs:18`. The JS
`Array.isArray(parsedJsonObject)` evaluates to `false`; the early-return
emits the literal "No players match" placeholder for every non-empty
result. **The verb-engine palette's marquee D-10 two-step flow never
returns a player row** — every target-required action ("Ban player",
"Unban player", "GDPR-delete player", "Adjust player rank",
"Delete admin") cannot be dispatched from the palette.

**Fix:** Drill into `.items` before rendering; preserve defensive guards:

```javascript
.then(function (r) { return r.ok ? r.json() : { items: [] }; })
.then(function (page) {
  var rows = (page && Array.isArray(page.items)) ? page.items : [];
  _renderTargetResults(rows);
})
```

### BLOCKER-03: Target-less palette actions dispatch `""` as Guid — silent dialog failure for "Create admin" and "Rotate signing key"

**Files:**
- `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js:269-275, 344-353`
- `src/GameKit.Admin.UI/Components/Layout/MainLayout.razor:107`

**Issue:** When an action row has `data-requires-target="false"` (per
`AdminCommandRegistry`: `create-admin`, `rotate-signing-key`,
`sign-out`, every `nav.*`), the click delegator at gamekit-admin.js:273
dispatches via `_dispatchOpenDialog(commandId, '', '')`. This bridges
through `invokeDialog → _dotNetRef.invokeMethodAsync('OpenDialog',
commandId, '', '')`.

The .NET endpoint signature is:
```csharp
public async Task OpenDialog(string commandId, Guid targetId, string targetName)
```

Blazor JS interop will attempt to deserialize the JS string `""` as
`Guid`; `System.Text.Json` throws `JsonException` for empty-string→Guid.
The `.catch(function () { return false; })` chain at gamekit-admin.js:162
swallows the exception silently. Operator impact: clicking "Create admin"
or any other target-less row in the palette closes the palette
(`closePalette()` at line 274) and does nothing else — no dialog opens,
no error toast, no console log. The `D-09` action set is broken for
every target-less verb.

**Fix:** Either pass `Guid.Empty` (zero GUID `"00000000-0000-0000-0000-000000000000"`)
from the JS, OR change the C# parameter type to `string targetId` and
parse internally:

Option A (JS-side, smallest diff):
```javascript
function _dispatchOpenDialog(commandId, targetId, targetName) {
  …
  invokeDialog(commandId,
               targetId || '00000000-0000-0000-0000-000000000000',
               targetName || '');
}
```

Option B (C#-side, more robust against future drift):
```csharp
[JSInvokable]
public async Task OpenDialog(string commandId, string targetId, string targetName)
{
    var pid = Guid.TryParse(targetId, out var g) ? g : Guid.Empty;
    var parameters = new DialogParameters
    {
        ["PlayerId"] = pid,
        ["DisplayName"] = targetName ?? string.Empty,
    };
    …
}
```

### BLOCKER-04: `nav.*` palette rows dispatch as dialogs — every navigation row is dead

**Files:**
- `src/GameKit.Admin.UI/Services/AdminCommandRegistry.cs:48-58` (10 nav rows)
- `src/GameKit.Admin.UI/Components/Layout/MainLayout.razor:114-125`
- `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js:269-275`

**Issue:** The registry declares 10 navigation rows
(`nav.dashboard`, `nav.players`, `nav.matches`, `nav.audit`, `nav.health`,
`nav.matchmaking`, `nav.rank-adjust`, `nav.admins`, `nav.login`,
`nav.player-detail`) all with `RequiresTarget: false`. The JS click
delegator treats them like target-less actions and calls
`_dispatchOpenDialog("nav.dashboard", '', '')` (compounded with
BLOCKER-03), which routes into `MainLayout.OpenDialog`. The switch
statement only maps the 5 dialog command ids — every `nav.*` falls into
`_ => null` and `OpenDialog` returns silently. The palette's
`Navigate` section closes on click and does nothing — `Cmd+K → "Go to
Audit log"` is non-functional.

Independent of BLOCKER-03's Guid issue, the dispatch path is wrong:
nav rows should call `NavigationManager.NavigateTo(href)`, not open a
dialog.

**Fix:** Branch on the command id prefix in the JS delegator and dispatch
nav rows via `Blazor.navigateTo` or via a separate `[JSInvokable]`
`Navigate(string url)` method on `MainLayout`. Map command ids to URLs
either in a sibling JS table or via a `Url` property on
`AdminCommandDto`:

```csharp
// Add Url to AdminCommand + AdminCommandDto:
public sealed record AdminCommand(string Id, string Label, string Category,
    bool RequiresSuperadmin, bool RequiresTarget, string? Url = null);

// Registry:
new("nav.dashboard", "Go to Dashboard", "nav", …, Url: "/admin"),
…

// JS click handler (replacement for the unconditional OpenDialog dispatch):
if (commandId.indexOf('nav.') === 0) {
  var url = row.getAttribute('data-url');
  if (url) window.location.href = url;
  closePalette();
  return;
}
```

The `nav.player-detail` row in particular makes no sense as a palette
verb (it requires a player target but is registered with
`RequiresTarget: false`); delete it or move it under "actions" with
`RequiresTarget: true` and a navigate-not-dialog path.

## Warnings

### WARNING-01: Tweaks-panel selection state is never reflected — every option button always looks unpicked

**Files:**
- `src/GameKit.Admin.UI/Components/Shared/TweaksPanel.razor.css:72-76`
- `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js:58-77`
- `src/GameKit.Admin.UI/Components/Shared/TweaksPanel.razor` (markup-only)

**Issue:** `TweaksPanel.razor.css` styles the active option via
`.tweaks-options button[aria-checked='true']` — but neither the Razor
markup nor `gamekit-admin.js` sets `aria-checked="true"` on the chosen
option. The Razor file is markup-only ("Markup-only component: no @code
state.") and the JS `saveTweaks/applyAttrs` only writes
`[data-*]` attributes on `<html>`. Operator impact: the Tweaks drawer
opens, the user clicks "Comfortable", the underlying `[data-density]`
attribute does flip and the page re-densifies — but the "Comfortable"
button itself shows no visible "I am the chosen one" treatment, so the
user has no way to see the current selection. UX regression vs the
sketch which clearly shows the active button.

**Fix:** Have `applyAttrs(t)` in `gamekit-admin.js` also iterate the
panel buttons and set `aria-checked` based on `data-tweak`/`data-value`:

```javascript
function applyAttrs(t) {
  var html = document.documentElement;
  Object.keys(ATTR_MAP).forEach(function (k) {
    html.setAttribute(ATTR_MAP[k], t[k] || DEFAULTS[k]);
  });
  // Reflect selection state on the panel buttons.
  document.querySelectorAll('[data-tweak]').forEach(function (btn) {
    var k = btn.getAttribute('data-tweak');
    var v = btn.getAttribute('data-value');
    btn.setAttribute('aria-checked', (t[k] || DEFAULTS[k]) === v ? 'true' : 'false');
  });
}
```

### WARNING-02: JS hardcodes `/admin/api/players/search` — any non-default `MountPath` 404s the palette target search

**File:** `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js:306`

**Issue:** `GameKitAdminOptions.MountPath` defaults to `/admin` and is
host-configurable; `AdminCspNonceMiddleware` and `MapGameKitAdmin` honor
the option. The new vanilla-JS bundle hardcodes the default:

```javascript
fetch('/admin/api/players/search?query=' + encodeURIComponent(q), …)
```

A consumer who configures `options.MountPath = "/console"` ends up with
the Razor pages at `/console/*` and the API at `/console/api/*`; the
target-search fetch hits `/admin/api/players/search` and 404s. This is a
new regression introduced by this phase (the JS bundle is new).

**Fix:** Render the resolved mount-path into an inline data attribute or
JSON tag that the JS reads on first run. Easiest: add to `App.razor`
inline init:

```razor
<script nonce="@Nonce">
  window.GKAdminConfig = {
    apiBase: '@(Options.MountPath.Value)/api'
  };
  // existing tweaks-init body...
</script>
```

```javascript
var apiBase = (window.GKAdminConfig && window.GKAdminConfig.apiBase) || '/admin/api';
fetch(apiBase + '/players/search?query=' + encodeURIComponent(q), …);
```

### WARNING-03: `Matches.razor` uses `async void` LocationChanged handler — unobserved exceptions crash the host

**File:** `src/GameKit.Admin.UI/Components/Pages/Matches.razor:99-103`

**Issue:**

```csharp
private async void OnLocationChanged(object? sender, LocationChangedEventArgs e)
{
    await ReadAndLoadAsync();
    StateHasChanged();
}
```

Any exception thrown by `ReadAndLoadAsync` (DB unavailable, malformed
query string with `Guid.TryParse` returning false but the EF query
failing on a stale connection, etc.) on the `async void` continuation
unwinds onto the synchronization context — in ASP.NET Core that surfaces
through the `IHostApplicationLifetime` and crashes the Blazor circuit
without a recoverable user-facing error.

**Fix:** Use `EventHandler` registration with a fire-and-forget that
catches its own exceptions:

```csharp
private void OnLocationChanged(object? sender, LocationChangedEventArgs e)
    => _ = HandleLocationChangedAsync(e);

private async Task HandleLocationChangedAsync(LocationChangedEventArgs _)
{
    try
    {
        await ReadAndLoadAsync();
        await InvokeAsync(StateHasChanged);
    }
    catch (Exception ex)
    {
        // log + best-effort surface to user; do NOT propagate to circuit
    }
}
```

### WARNING-08: `_filterPalette` section grouping is fragile — relies on textContent equality for keying

**File:** `src/GameKit.Admin.UI/wwwroot/gamekit-admin.js:184-209`

**Issue:**

```javascript
var sectionVisible = {};
rows.forEach(function (row) {
  …
  var section = row.previousElementSibling;
```

### WARNING-09: Empty-string fallthrough `??= AdminRoles.Admin` masks principal misconfiguration

**Files:**
- `src/GameKit.Admin.UI/Http/AdminEndpoints.cs:482`
- `src/GameKit.Admin.UI/Components/Shared/CommandPalette.razor:97-98`

**Issue:** Both `GET /admin/api/commands` and the SSR `CommandPalette`
default the role claim to `AdminRoles.Admin` when missing:

```csharp
var role = http.User.FindFirst(ClaimTypes.Role)?.Value ?? AdminRoles.Admin;
```

The `[Authorize(Policy = AdminPolicies.Admin)]` gate has already run, so
the principal is authenticated — but the only legitimate way for the
role claim to be missing is a programming error (`SignInCoreAsync`
neglected to populate it, or the cookie predates a schema change). In
that case the fallback silently grants a "plain admin" view to whoever
is on the call — including, hypothetically, a stale cookie issued to a
non-admin role. Better to fail closed:

**Fix:**

```csharp
var role = http.User.FindFirst(ClaimTypes.Role)?.Value;
if (string.IsNullOrEmpty(role)) return Results.Forbid();
var isSuper = string.Equals(role, AdminRoles.Superadmin, StringComparison.Ordinal);
…
```

Mirror the same change in `CommandPalette.OnInitializedAsync` — set
`_visible = Array.Empty<AdminCommandDto>()` when the role claim is
absent rather than falling back to the admin-set.

## Info

### INFO-01: `_navSubscription` and other dead initializations

`Matches.razor:94` writes `_navSubscription = null;` — the field's
default is already `null`. Pure ceremony.

### INFO-02: Inline `style="..."` blocks on Dashboard cards mix concerns

`Dashboard.razor:83, 129, 133` write `style="padding:16px;"` and
`style="margin-top:12px;"` directly on markup. CSP `style-src` allows
`'unsafe-inline'` so this works, but the codebase otherwise drives layout
via class names + scoped CSS — these inline styles undermine the
discipline. Move to `.gk-dashboard-stat-stack { … }` in the page's
scoped CSS file.

### INFO-03: `AuditSentenceTemplates.Render` swallows `JsonException` differently from `InvalidOperationException`

`AuditSentenceTemplates.cs:114, 132` catch only `InvalidOperationException`
when extracting rating delta / role; the JSON helpers can also throw
`FormatException` (for malformed numeric strings) and
`JsonException` (when accessing a property on the wrong kind under
some upstream library updates). Catching the specific types is fine but
the methods are best-effort fallbacks — a broader `catch (Exception)`
with a debug log would be more resilient and would not re-introduce the
"silent crash on bad data" pattern.

### INFO-04: `CssBundleSizeTests` path computation is brittle

`tests/GameKit.Admin.Tests/Bundle/CssBundleSizeTests.cs:24-25` uses a
hard-coded `"../../../../../src/GameKit.Admin.UI/wwwroot/gamekit-admin.css"`
relative to `AppContext.BaseDirectory`. Any change to the test
project's TFM (`net10.0` → `net11.0`) or assembly-name shifts the hop
count and the test breaks with a `File.Exists` assertion failure
rather than a clear "I cannot find the file" message. Resolve via
`MSBuildProjectDirectory` propagated through a `[Theory]` data source
or via an `[AssemblyFixture]` that walks upward looking for `.git`.

### INFO-05: `Audit.razor` ignores cancellation tokens — fixed `CancellationToken.None` bypass

`Audit.razor:201` and `PlayerDetailPane.razor:227` both pin
`var ct = CancellationToken.None;` for their EF queries. The component
disposes during navigation (master-detail nav fires
`OnParametersSetAsync` repeatedly), so an in-flight EF query has no
back-pressure path and the result is discarded after rendering. Pass a
component-scoped `CancellationTokenSource` and cancel on
`Dispose`/`OnParametersSetAsync` — Players.razor already implements this
pattern correctly (`_cts` + `IDisposable`); the same pattern is missing
from Audit and PlayerDetailPane.

### INFO-06: Public XML doc compliance is solid except for `BanBanner.OnUnbanRequested`

CLAUDE.md mandates "XML doc comments on every public API — no
exceptions". `BanBanner.razor:56` does have a comment, but
`PlayerDetailPane.razor`'s public `Id` parameter docs are accurate.
Check pass on the new files (`AdminCommandDto`, `SentenceModel`,
`AdminCommand`, `AdminCommandRegistry`, `SentenceContext`,
`AuditSentenceTemplates.Render`, `BanBanner` parameters,
`ChipRail.ChipItem`). The single blemish: `MainLayout.OpenDialog` is
`public` but its scope is internal-by-intent (only the JS bridge calls
it). Consider marking it `internal` (it has the `[JSInvokable]` attribute
which keeps it reachable) — or document explicitly that it is not part
of the consumer surface.
