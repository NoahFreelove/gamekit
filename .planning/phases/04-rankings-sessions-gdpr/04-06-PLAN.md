<objective>
The Rankings ticker is the runtime heart of Phase 4. It runs as a BackgroundService, acquires a Redis distributed lock for leader election, scans active ladders for elapsed rating periods, drains pending_rating_updates rows in per-ladder batches, applies IRankingAlgorithm.Apply once per batch, snapshots results onto player_ranks and session_participants, and tolerates Redis disconnects via Polly v8 retry. The idempotency cleanup service runs nightly. RANK-06 / SC#1 demands a 1000-match convergence test.

Purpose: This plan delivers the algorithmic loop that turns enqueued rating updates into real ratings (RANK-07 lazy creation + RANK-04 batched-only invariant). The Redis lock prevents two replicas from double-applying ratings; the Polly retry tolerates Redis hiccups; the per-ladder transaction isolates failure radius (D-04). SC#1 is the gating proof that the whole loop converges.

Output: RankingsTickerService + lease helper + IdempotencyCleanupService + three integration tests covering leader election, lazy rank creation, and the 1000-match convergence (SC#1).
</objective>
