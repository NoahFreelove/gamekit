<objective>
Deliver the seasonal-reset capability (RANK-10) and the leaderboard query surface (RANK-08), and light up the Phase-3 admin palette verb end-season (currently a registered no-op slot per CONTEXT D-11). This plan establishes SeasonArchiveLeaderboardTests as the SC#4 anchor.

Purpose: Seasons are the operational rhythm for competitive ladders. Ending a season must be atomic across four mutations (close current season + open new + archive ranks + apply reset policy) AND write an audit row. The Phase-3 admin shell already has the palette infrastructure; this plan provides the dialog + service + endpoint that finally wires the verb. Leaderboards are a thin service surface in v1 (admin-only HTTP exposure; player-facing leaderboard HTTP is deferred per CONTEXT Deferred Ideas).

Output: EndSeasonService (SERIALIZABLE tx, three reset variants), LeaderboardService (TopAsync + AroundAsync), POST /admin/api/ladders/{id}/end-season + GET /admin/api/leaderboard endpoints, EndSeasonDialog.razor + palette wiring + audit-action + sentence-template additions, SeasonArchiveLeaderboardTests (SC#4).
