<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| login request → IPasswordHasher.Verify | Untrusted plaintext password + stored hash cross into the hasher. Hash format determines which verifier runs (BCrypt vs Argon2id). |
| build → NuGet supply chain | New package installs (Isopoh.*) cross the supply-chain boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Spoofing | Argon2 params downgrade (weak m/t/p baked into defaults) | mitigate | Defaults m=65536/t=3/p=1 exceed OWASP 2025 minimums (m≥19456, t≥2); enforced by GameKitArgon2Options defaults; a unit test asserts MemoryCost≥19456 and TimeCost≥2 (add to Argon2HasherTests). |
| T-07-02-02 | Tampering | Hash-format confusion in dual-verify (Argon2 verifier fed a BCrypt hash or vice versa) | mitigate | Explicit `$2a$`/`$2b$` prefix branch routes to BCrypt.Verify; Argon2.Verify handles only `$argon2id$`; malformed input returns false (caught), never throws. Covered by malformed-hash and BCrypt-compat tests. |
| T-07-02-03 | Information Disclosure | Timing oracle: NeedsRehash on the dummy-hash path leaks user-not-found | accept | The existing `PasswordOAuthProvider.DummyHash` is a `$2a$12$` BCrypt literal; on Argon2, NeedsRehash returns true for it but the dummy path (user-not-found) never reaches the rehash UPDATE (no credential row). Full timing-parity wiring is verified in Plan 06; no new oracle introduced here. |
| T-07-02-04 | Denial of Service | Argon2 memory exhaustion under concurrent login burst (64 MiB/verify) | accept | Lanes=1/Threads=1 caps per-verify memory to 64 MiB; documented in GameKitArgon2Options XML as a tuning knob for hosts exceeding ~50 concurrent logins. Acceptable default per RESEARCH §Security Domain. |
| T-07-02-SC | Tampering | `Isopoh.Cryptography.Argon2` + Blake2b + SecureArray NuGet installs | mitigate | RESEARCH §Package Legitimacy Audit approves all three (nuget.org, ~8yr age, 7M+ downloads, github.com/mheyman, CC0). slopcheck [SLOP] verdicts are PyPI-vs-NuGet false positives. Packages are first-party-verified; no `[ASSUMED]`/`[SUS]` entries, so no blocking-human checkpoint required. |
</threat_model>
