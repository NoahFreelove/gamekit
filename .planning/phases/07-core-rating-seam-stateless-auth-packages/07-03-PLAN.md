<objective>
Ship `GameKit.Auth.Google` (AUTH-19, AUTH-22): an opt-in sibling package wrapping `Microsoft.AspNetCore.Authentication.Google` 10.0.8. It provides a `GoogleOAuthProvider : IOAuthProvider` (discriminator `"google"`) that upserts a `PlayerIdentity` keyed by the Google `sub` claim (NOT email) under the existing `UNIQUE(provider, external_id)` contract, plus an `AddGoogle()` builder extension that self-registers the provider and conditionally registers the Google authentication scheme.

Purpose: Covers a top-tier identity provider for game backends with zero new database surface — `player_identities` already stores `provider` as a free-form discriminator.

Output: Google package (5 source files) + test project. ZERO migrations.

This plan depends on Plan 02 (07-02) for the `Directory.Packages.props` pin of `Microsoft.AspNetCore.Authentication.Google` and the `GameKit.sln` project entries. It shares NO files with Plans 04/05/06 and runs fully parallel with them in Wave 2.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google IdP → OnCreatingTicket | The ASP.NET Core Google handler verifies the OAuth code/token; the verified principal's claims cross into GoogleOAuthProvider. The `sub` claim is the trusted identity key. |
| OnCreatingTicket → player_identities | Upsert under UNIQUE(provider, external_id) — the identity-linking boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03-01 | Spoofing / Identity Confusion | Using email instead of `sub` as external_id | mitigate | OnCreatingTicket extracts `sub` via `ClaimTypes.NameIdentifier` only; email is informational. Asserted by the provider discriminator test + grep gate for `ClaimTypes.NameIdentifier`. |
| T-07-03-02 | Elevation of Privilege | Identity takeover via duplicate (provider, external_id) | mitigate | Upsert respects the existing `UNIQUE(provider, external_id)` constraint on PlayerIdentity; a second login with the same sub maps to the same player. Inherited from the Discord-proven flow. |
| T-07-03-03 | Tampering | Provider not discovered at runtime (Scrutor scope gap) → 404 / wrong-provider | mitigate | Explicit `AddScoped<IOAuthProvider, GoogleOAuthProvider>()` in AddGoogle (sibling assembly not scanned by the Auth Scrutor scan). Verified by the DI_Smoke test. |
| T-07-03-04 | Denial of Service | Google handler throws in a test harness without credentials | mitigate | Conditional scheme registration (only when ClientId+ClientSecret present) mirrors the v1 Discord pattern; verified by ConditionalScheme_Absent test. |
| T-07-03-SC | Tampering | `Microsoft.AspNetCore.Authentication.Google` NuGet install | mitigate | RESEARCH §Package Legitimacy Audit approves it (Microsoft first-party, github.com/dotnet/aspnetcore, 100M+ downloads, MIT). Pinned by Plan 02. No `[ASSUMED]`/`[SUS]` — no blocking-human checkpoint required. |
</threat_model>
