<objective>
Ship `GameKit.Auth.Epic` (AUTH-21, AUTH-22): an opt-in sibling package with a CUSTOM `OAuthHandler<EpicOAuthOptions>` against Epic's standard OAuth 2.0 endpoints — zero new NuGet dependency (OAuthHandler<T>/OAuthOptions are in the ASP.NET Core shared framework). It provides an `EpicOAuthProvider : IOAuthProvider` (discriminator `"epic"`) that upserts a `PlayerIdentity` keyed by Epic's account id under the existing `UNIQUE(provider, external_id)` contract, and an `AddEpic()` builder extension that self-registers the provider and conditionally registers the Epic scheme.

Critical detail (RESEARCH §Pitfall 6 / Open Q2): Epic's token endpoint uses HTTP Basic auth for the client id/secret, NOT form fields. `EpicOAuthHandler` overrides `ExchangeCodeAsync` to inject `Authorization: Basic base64(clientId:clientSecret)`. This is unit-testable against a WireMock stub; the live EOS round-trip needs sandbox credentials (human-verify gate).

Purpose: Epic is a top game-identity provider with no maintained .NET package; a small custom handler keeps the supply chain clean.

Output: Epic package (7 source files) + test project. ZERO migrations.

`autonomous: false` because the live EOS round-trip and the definitive token-endpoint auth-method confirmation need sandbox credentials. The handler shape, Basic-auth override, token exchange against WireMock, and DI wiring are ALL automated. Depends on Plan 02 (07-02) for sln entries (Epic adds NO new package pin). | Boundary | Description |
|----------|-------------|
| Epic IdP → EpicOAuthHandler | The custom handler exchanges the auth code and calls userInfo; Epic's `account_id` crosses in as the trusted identity key. |
| EpicOAuthHandler → Epic token endpoint | Client credentials cross via the Authorization: Basic header (must not be logged). |
| OnCreatingTicket → player_identities | Identity upsert under UNIQUE(provider, external_id). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05-01 | Information Disclosure | Client secret leaked in logs/form body | mitigate | Credentials are sent only in the Authorization: Basic header inside ExchangeCodeAsync; the handler never logs the header. Verified by the WireMock Basic-auth test (no form-field client_secret). |
| T-07-05-02 | Spoofing / Identity Confusion | Email or display_name used as external_id instead of stable account_id | mitigate | CreateTicketAsync maps Epic `account_id` to `ClaimTypes.NameIdentifier`; OnCreatingTicket extracts NameIdentifier as external_id. Epic does not offer email-based merge (RESEARCH §Known Threat Patterns). |
| T-07-05-03 | Tampering | Provider not discovered (Scrutor scope gap) | mitigate | Explicit `AddScoped<IOAuthProvider, EpicOAuthProvider>()`; verified by DI_Smoke. |
| T-07-05-04 | Denial of Service | Custom handler throws in a credential-less test harness | mitigate | Conditional scheme registration (ClientId+ClientSecret present); verified by ConditionalScheme_Absent. |
| T-07-05-05 | Tampering | Live Epic endpoint rejects the assumed Basic-auth method (RESEARCH Open Q2) | mitigate | Wire format proven against a stub; the live confirmation is the blocking human-verify gate (Task 4) with a documented fallback (switch to form-body auth) if Epic returns 400. |
| T-07-05-SC | Tampering | npm/pip/cargo installs | n/a | Epic adds ZERO new NuGet packages (OAuthHandler<T> is shared-framework; WireMock.Net is a pre-existing test-only pin). No legitimacy checkpoint required. |
