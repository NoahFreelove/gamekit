<objective>
Implement RANK-16 placement decrement and RANK-17 `RankingsRatingSource`. Session-complete atomically decrements `placement_matches_remaining` (flipping `is_in_placement` to false at zero) inside the existing ambient transaction; `RankingsRatingSource : IPlayerRatingProvider` projects `player_ranks` into Core `PlayerRatingValue`, wired via `.WithRatingsFrom<RankingsRatingSource>()` using `RemoveAll + AddScoped` to override the Core null-object.

Purpose: this is the Rankings side of rating-aware play. The rating source is the seam plan 08-04's matchmaking wire consumes (cross-package, Core interface only). Placement completion is server-authoritative and rides the session-complete transaction so it cannot be gamed or double-counted.

Output: the decrement at the session-complete hook, `RankingsRatingSource`, the `.WithRatingsFrom<>()` builder partial, and tests proving atomic decrement, correct projection/omission, and null-object override.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → session-complete | The number of placement games completed is server-authoritative — a client must not be able to short-circuit placement |
| concurrent session-completes → player_ranks | Two completions for the same player must not double-decrement or underflow PlacementMatchesRemaining |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03-01 | Tampering | placement decrement | mitigate | ExecuteUpdateAsync with `WHERE IsInPlacement AND PlacementMatchesRemaining > 0` race guard inside the ambient ReadCommitted tx; cannot underflow below 0; no client endpoint writes placement state (RESEARCH §Security: placement is server-authoritative) |
| T-08-03-02 | Information Disclosure | RankingsRatingSource projection | accept | Returns rating values only to in-process matchmaking callers (Core seam), never directly to a client; visible-rank hiding for clients is enforced in 08-01 DTOs, not here |
| T-08-03-03 | Tampering | WithRatingsFrom registration | mitigate | RemoveAll + AddScoped (not TryAdd) guarantees the override actually takes effect; registration unit test asserts the resolved provider is RankingsRatingSource, preventing a silent fallback to the null-object |
| T-08-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this phase (RESEARCH §Package Legitimacy Audit: none) |
</threat_model>
