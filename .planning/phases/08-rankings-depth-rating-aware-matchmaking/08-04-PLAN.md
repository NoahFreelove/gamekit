<objective>
Implement MATCH-16 (rating-aware enqueue) and MATCH-17 (anti-feedback-loop guardrails) together as one unit — the guardrails MUST ship in the same plan/wave as the rating wire, never as a follow-up. `MatchmakingService.EnqueueAsync` resolves the Core `IPlayerRatingProvider` and caches each member's real rating into the Redis ticket hash (replacing `Rating: 0` at line 202-204); `EloRangeMatchmakingStrategy` gains a `MaxBracketWidth` hard cap and a `MinPoolDepthBeforeBracketExpansion` guard, both validated at `AddLadder`.

Purpose: real Glicko-2 ratings make EloRange brackets meaningful, but without guardrails a new high-RD player on a sparse pool would funnel into top-rated matches. Shipping the cap + depth guard simultaneously closes that feedback loop the moment real ratings flow. Matchmaking consumes only the Core interface — no hard Rankings dependency, so the package still works (zero-rated) when Rankings is absent.

Output: the rating-aware enqueue, the two guardrail fields + their enforcement + validation, a unit test for the guardrails, and a cross-package Testcontainers test proving SC#3 (real ratings in the ticket hash) and SC#4 (bracket stops at MaxBracketWidth regardless of pool depth).
</objective>
