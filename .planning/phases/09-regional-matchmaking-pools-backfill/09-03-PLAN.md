## Trust Boundaries

|----------|-------------|
| client → POST /api/matchmaking/backfill | untrusted SessionId/LadderId/RegionName; RegionName becomes a Redis key component |
| BackfillService → Postgres/Redis | creates a privileged score-0 (highest-priority) ticket — must be gated by authn + session-active checks |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03-01 | Elevation of Privilege | backfill creates a top-priority (score 0) ticket | mitigate | Endpoint .RequireAuthorization() + player id from JWT NameIdentifier (TryGetPlayerId → Results.Forbid on missing claim); only authenticated players can create a backfill ticket |
| T-09-03-02 | Tampering | RegionName as Redis key component | mitigate | FluentValidation `^[a-zA-Z0-9\-]+$` + MaximumLength(64) on BackfillRequest.RegionName AND server-side AllowedRegions check in BackfillService (mirror of Plan 02) |
| T-09-03-03 | Denial of Service | flooding POST /api/matchmaking/backfill to saturate the queue with priority-0 tickets | mitigate | Reuse the existing gamekit:mm:enqueue rate-limit policy (.RequireRateLimiting(names.MmEnqueue)); plus session-must-be-Active check rejects backfill against arbitrary/closed sessions |
| T-09-03-04 | Spoofing | backfill into a session the player has no relationship with | accept | SC#3 scope is "creates a backfill-typed ticket"; the game server decides match formation. Session-existence + Active gate is enforced; deeper membership policy is out of phase scope (09-RESEARCH.md Open Question 1) |
| T-09-03-SC | Tampering | npm/pip/cargo installs | accept | No package installs this phase (09-RESEARCH.md Package Legitimacy Audit: none) |
