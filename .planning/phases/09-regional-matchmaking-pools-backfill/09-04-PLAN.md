<objective>
Implement the MATCH-19 participation-fraction rating guard: a backfill (or any under-participating) player whose session_participants.ParticipationFraction is below the ladder's configured minimum never enters the rating batch — the PendingRatingUpdate INSERT is skipped, so IRankingAlgorithm.Apply (which operates per-batch) simply never sees that player's outcome. No rating change, no W/L/D increment.

The guard reads the threshold from the ladder JSONB Config (the clean approach — zero Matchmaking→Rankings runtime coupling, mirroring how RatingPeriodSeconds/DefaultRating are read). The Rankings LadderConfig gains MinParticipationFractionForRating and StartupLadderUpserter persists it into JSONB at startup.

Purpose: Closes SC#4 (ParticipationFraction below minimum → no rating change; IRankingAlgorithm.Apply guard fires correctly). Turns BackfillParticipationTests (scaffolded RED in Plan 01) green.
Output: LadderConfig field, StartupLadderUpserter JSONB write, adapter guard + JSONB read helper, BackfillParticipationTests filled in.

Note on wave: this plan runs in Wave 2 (parallel with Plan 02) — it touches only Rankings source + one test file, with no overlap against Plans 02/03. It depends only on Plan 01's ParticipationFraction column + the migration.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| game server → session_participants.ParticipationFraction | the participation fraction is written by the consumer's game server; the guard trusts it as authoritative match telemetry |
| ladder JSONB Config → adapter | MinParticipationFractionForRating crosses from config persistence into the rating-skip decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04-01 | Tampering | game-server-supplied ParticipationFraction used to dodge a rating loss | accept | The game server is a trusted first-party component in the self-hosted model (the developer owns it); GameKit cannot independently verify presence. Builder-time range validation (Plan 01) bounds the configured threshold; the fraction itself is consumer telemetry. Documented residual risk |
| T-09-04-02 | Denial of Service | malformed JSONB Config crashes the adapter mid-drain | mitigate | ReadMinParticipationFraction wraps the JSON read in try/catch and returns null (no guard) on any parse error — a corrupt Config never throws inside OnCompletedAsync, preserving the rating drain |
| T-09-04-03 | Repudiation | silent skip of a rating update is indistinguishable from a missing match | accept | SC#4 specifies the under-participating player receives NO rating change and NO W/L/D increment — silent skip is the intended behaviour; the session_participants row retains ParticipationFraction as the audit trail of why |
| T-09-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs this phase (09-RESEARCH.md Package Legitimacy Audit: none) |
</threat_model>
