<objective>
Implement `AccountMergeService` — the SERIALIZABLE, crash-resumable, fully-audited engine that irreversibly merges a source player into a target. This is the milestone's highest-risk operation; favor crash-safety, idempotency, and auditability. Covers FK re-pointing across every table with a FK to players(id) (SC#2/AUTH-23), the account_merges state machine + crash-resume (SC#1/AUTH-24), player_ranks conflict resolution (SC#3/AUTH-25), the before/after audit row (SC#4/AUTH-26), and the guard policies (self-merge, already-merged, party conflict, banned target).

Purpose: This service is the single source of truth for the merge; the Plan 04 endpoint is a thin authz/validation shell over `IAccountMergeService.MergeAsync`.

Output: IAccountMergeService + AccountMergeService + DI registration.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller (Admin endpoint) → AccountMergeService | source/target ids cross from authz layer; service must self-guard |
| process crash → DB/Redis state | a kill between commit and Redis cleanup leaves a resumable checkpoint |
| source player identity → target player | irreversible re-homing of all FKs; partial state is corruption |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-01 | Tampering | partial merge on mid-tx crash | mitigate | All re-points inside one SERIALIZABLE tx; rollback is atomic; only the post-commit Redis cleanup is non-transactional and is resumable via redis_cleaned checkpoint |
| T-10-03-02 | Elevation of Privilege | concurrent merges race on same source | mitigate | SERIALIZABLE + 40001 retry (3 attempts) + UNIQUE(account_merges.SourcePlayerId) from Plan 02; first writer wins |
| T-10-03-03 | Repudiation | double-merge / replay produces duplicate audit or double revoke | mitigate | Resume ladder: committed/redis_cleaned return AlreadyMerged; audit written only on Pending->Committed; RevokeAllForPlayerAsync called only on the Pending path (SC#1) |
| T-10-03-04 | Information Disclosure | source player_id leaked via audit/result | mitigate | MergeResult carries only TargetPlayerId; audit TargetId=target; source id only inside Before-JSON (superadmin-restricted) |
| T-10-03-05 | Tampering | merge a banned account into a legitimate one | mitigate | Abort if target.IsBanned (TargetBanned); banned-source allowed but recorded in audit metadata (A3) |
| T-10-03-06 | Tampering | self-merge or already-merged source corrupts state | mitigate | Guards reject SelfMerge (source==target) and SourceAlreadyMerged (MergedIntoPlayerId != null) before any mutation |
| T-10-03-07 | Tampering | source-in-party UNIQUE(party_id,player_id) corruption | mitigate | Pre-mutation party-conflict JOIN -> PlayersInSameParty abort (RESEARCH party_members decision; LastSuperadmin abort precedent) |
| T-10-03-08 | Denial of Service | stale Redis matchmaking keys after merge | accept | Keys TTL-expire; source tokens revoked so no phantom proposal acceptable (Pitfall 7) |
| T-10-03-SC | Tampering | npm/pip/cargo installs | accept | No package installs (zero new deps per 10-RESEARCH Package Legitimacy Audit) |
</threat_model>
