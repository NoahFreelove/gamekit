# Phase 14 — UI Design Contract

> Visual and interaction contract for Phase 14: Health & Readiness.
> Generated by gsd-ui-researcher. This is a documentation-of-existing-contract spec.
> There is NO new visual design in this phase. All decisions are LOCKED from existing
> code (Health.razor, HealthTileView.razor, gamekit-admin.css) and CONTEXT.md (D-15/D-16).

---

## Scope Reality

Phase 14 has exactly ONE UI-relevant change: `HealthProbeService` is refactored to delegate
its Postgres and Redis data to Core's `HealthCheckService` instead of opening its own
`NpgsqlConnection` / calling `IDatabase.PingAsync()` directly (D-15). The Health page
(`/admin/health`), its layout, components, CSS classes, status strings, and refresh
mechanism are ALL PRESERVED. No new pages, routes, dialogs, or components are created.

The new `/health/live` and `/health/ready` HTTP endpoints are machine/orchestrator JSON —
they are NOT rendered in the Admin UI and are entirely outside this contract's scope.

## Status → Visual Mapping (LOCKED)

This is the central design contract for D-15. The mapping is implemented in `StatusChip.razor`
and must be preserved exactly as documented here.

| `HealthTile.Status` string | CSS chip class | Dot color | Chip bg / text / border |
|---------------------------|---------------|-----------|------------------------|
| `"OK"` | `.chip.healthy` | `--green` (`#16A34A`) | `--green-bg` / `#166534` / `--green-border` |
| `"Degraded"` | `.chip.degraded` | `--amber` (`#D97706`) | `--amber-bg` / `#92400E` / `--amber-border` |
| `"Down"` | `.chip.down` | `--red` (`#DC2626`) | `--red-bg` / `#991B1B` / `--red-border` |

Source mapping in `HealthProbeService` after D-15 refactor (LOCKED by CONTEXT.md D-15):

| `HealthStatus` from `HealthCheckService` | `HealthTile.Status` |
|------------------------------------------|---------------------|
| `Healthy` | `"OK"` |
| `Degraded` | `"Degraded"` |
| `Unhealthy` | `"Down"` |
| (entry absent — check not registered) | `"Down"` with detail `"not configured"` |

The `"not configured"` value for an absent Redis entry (when `IConnectionMultiplexer` is
absent from DI) maps to `.chip.down` visually. This is the existing behavior for
Redis-unconfigured installs and is preserved unchanged.

## Tile Data Contract (LOCKED)

`HealthReport` and `HealthTile` records in `GameKit.Admin.UI/Http/Contracts/HealthReport.cs`
are preserved without modification (D-16).

```csharp
record HealthReport(
    HealthTile Postgres,    // sourced from HealthCheckService "postgres" entry (D-15)
    HealthTile Redis,       // sourced from HealthCheckService "redis" entry (D-15)
    HealthTile ErrorRate,   // sourced from ErrorRateRingBuffer / IRedisErrorRateCounter (D-16 — Admin-local)
    DateTimeOffset CheckedAt);

record HealthTile(
    string Status,          // "OK" / "Degraded" / "Down"
    string Detail,          // human-readable description, never a connection string or exception message
    double? LatencyMs);     // round-trip milliseconds; null for gauge-style tiles (ErrorRate)
```

Postgres and Redis tiles after D-15: `Detail` is sourced from `HealthReportEntry.Description`
(the hand-authored string written by each `IHealthCheck` implementation in Core — e.g.
`"connected"`, `"database unreachable"`, `"ping failed"`). `LatencyMs` is sourced from
`HealthReportEntry.Duration.TotalMilliseconds`.

ErrorRate tile: `Detail` continues to be `"{count} errors in window"` (unchanged). `LatencyMs`
remains null (gauge, no latency concept).

## Interaction Contract (LOCKED)

All interactions are unchanged from the existing implementation. Documented here for executor reference.

### Auto-refresh

- Timer: `System.Threading.Timer` initialized in `OnInitializedAsync`, period =
  `GameKitAdminOptions.Panel.RefreshInterval` (default 10 seconds).
- Interval label: displayed as `(int)Options.Panel.RefreshInterval.TotalSeconds` in the
  `.muted` caption.
- Concurrency guard: `if (_refreshing) return;` — a slow probe never queues a second
  concurrent probe.
- On probe failure: keep the last-known `_report` displayed; swallow the exception silently.
  The Refresh button remains available. No error toast for auto-refresh failures.
- Disposal: `IAsyncDisposable.DisposeAsync()` disposes the timer when the Blazor circuit tears down.

### Manual Refresh button

- Label: "Refresh" at rest; "Refreshing…" while `_refreshing == true`.
- Disabled attribute: `disabled="@_refreshing"` — button is non-interactive during probe.
- Click handler: `@onclick="RefreshAsync"`.
- Class: `.btn` (base secondary style — white background, `--border` border, 13px 600 weight).

### Page load

- `OnInitializedAsync` calls `RefreshAsync()` before starting the timer.
- Panel renders tiles immediately on first probe completion via `StateHasChanged()`.

### No destructive actions

The Health page has zero destructive actions. No confirmation dialogs.

| Tile label: column 1 | "Postgres" | `Health.razor` Label param |

| Tile label: column 3 | "Error rate" | `Health.razor` Label param |
| Loading placeholder | "…" (`aria-hidden="true"`) | `HealthTileView.razor` .v |
| Timestamp format | "updated HH:mm:ss UTC" | `HealthTileView.razor` .footer |
| Tile detail: Postgres OK | "connected" | Core `PostgresHealthCheck` (to implement) |
| Tile detail: Postgres Down | "database unreachable" | Core `PostgresHealthCheck` (to implement) |
| Tile detail: Redis OK | "ping ok" | Core `RedisHealthCheck` (to implement) |
| Tile detail: Redis Down | "ping failed" | Core `RedisHealthCheck` (to implement) |
| Tile detail: Redis not configured | "not configured" | `HealthProbeService.GetTile` fallback |
| Error-rate detail | "{N} errors in window" | `HealthProbeService.ProbeErrorRateAsync` (unchanged) |

Copywriting rules:
- Tile `Detail` strings from Core health checks MUST be human-readable and infra-free.
  Never include: exception type names, connection strings, hostnames, ports, or credential
  fragments. This is a hard requirement from HLTH-05 / D-12.
- The existing error-rate tile copies `"{N} errors in window"` are Admin-local (D-16) and
  unchanged.

Empty state: not applicable — the health panel always shows three tiles. While probing,
the loading placeholder `"…"` is shown in the `.v` slot of each tile.

Error state: probe failures are swallowed silently (keep last-known report). No user-visible
error copy is displayed for auto-refresh failures. The Refresh button always remains
clickable for a manual retry.

## Accessibility Contract (LOCKED)

Existing accessibility properties from `HealthTileView.razor` and `StatusChip.razor`:

| Element | ARIA / semantic | Rule |
|---------|----------------|------|
| Status chip | `role="status"` + `aria-label="{Status}"` | Color is NEVER the sole status indicator — the status string text is always visible inside the chip alongside the color dot |
| Tile loading state `.v` | `aria-hidden="true"` when `Tile is null` | The ellipsis `"…"` is decorative; screen readers skip it |
| Refresh button | `disabled="@_refreshing"` | Native disabled state; no ARIA override needed |
| Chip color dot | `<span class="dot">` | Decorative — no aria-label (text label on chip provides meaning) |

Status as text + color dual encoding is a LOCKED accessibility requirement. Implementing
status-only as color (removing the text from `.v` or from `StatusChip`) is forbidden.

## Data Source Change Summary (D-15)

This is the only behavioral change visible to the Health panel.

| Tile | Before (current) | After (D-15) |
|------|-----------------|--------------|
| Postgres | `HealthProbeService.ProbePostgresAsync` — opens `NpgsqlConnection`, runs `SELECT 1`, 2s timeout | `HealthCheckService.CheckHealthAsync()` entry `"postgres"` — `PostgresHealthCheck` in Core |
| Redis | `HealthProbeService.ProbeRedisAsync` — calls `IDatabase.PingAsync()` | `HealthCheckService.CheckHealthAsync()` entry `"redis"` — `RedisHealthCheck` in Core |
| Error rate | `HealthProbeService.ProbeErrorRateAsync` — reads `ErrorRateRingBuffer` / `IRedisErrorRateCounter` | UNCHANGED (D-16 — Admin-local, not a readiness dependency) |

The view-layer components (`Health.razor`, `HealthTileView.razor`, `StatusChip.razor`) require
ZERO changes. `HealthReport` and `HealthTile` records require ZERO changes. The visual output
is identical.
