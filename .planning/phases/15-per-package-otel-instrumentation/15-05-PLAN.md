<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SignalR client → hub | client-supplied lobbyId/message reach the hub; instrumentation must not echo identifiers into tags |
| hub invocation → ready-check span parent | `Activity.Current` captured server-side becomes the ReadyCheck span parent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-05-PII | Information Disclosure | lobby metrics + ReadyCheck span | mitigate | Only `check.result` (enum: `all_ready`, future `timeout`/`cancelled`) as a tag key; connected-clients gauge + message counter are untagged; no lobbyId/playerId tag. GK0001 (build) + `LobbyPiiTagKeyTests` (runtime, this plan) enforce the forbidden set (criterion #1). |
| T-15-05-TRACE | Spoofing | ReadyCheck span parent context | mitigate | Parent is `Activity.Current.Context` captured SERVER-SIDE from the SignalR hub invocation — never from client-supplied input; no `traceparent` is read from the message payload, so there is no client-influenceable trace-context-injection surface for the lobby path. |
| T-15-05-CARD | Denial of Service | instrument cardinality | mitigate | Connected-clients is a single untagged gauge; counters carry at most the bounded `check.result` enum — no per-connection/per-lobby cardinality. |
| T-15-05-SC | Tampering | package installs | accept | No new packages — in-box `System.Diagnostics.*`; SignalR already present. |
</threat_model>
