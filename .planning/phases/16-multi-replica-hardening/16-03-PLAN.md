<objective>
Fix the graceful-shutdown lease-release bug across all five background-service finally paths. Today each finally block calls `ReleaseLeaseAsync(ct)` where `ct` is the stopping token — already cancelled when the finally runs on SIGTERM — so StackExchange.Redis cancels the release command and the lock hangs until TTL expiry (90 s default), stalling leader re-election on the surviving replica. The fix is a one-token substitution per site: pass `CancellationToken.None` so the short, atomic, Lua-verified release survives shutdown. This is SCALE-02.

Purpose: Zero-downtime rolling deploys — the surviving replica becomes leader within seconds, not after a 90 s TTL holdover (RESEARCH §Graceful Shutdown, Pitfall 1). Required by SCALE-02.
Output: Five one-line fixes; a static grep gate proving no stopping-token release remains.
</objective>
