  <behavior>
    - Migration with `Down()` body `{ throw new NotSupportedException("..."); }` → NO diagnostic
    - Migration with `Down()` body containing `migrationBuilder.DropTable(...)` → GK0003 Error
    - Migration with EMPTY `Down()` body `{ }` → GK0003 Error (Pitfall 4)
    - Migration with `Down()` throwing a DIFFERENT exception (e.g. InvalidOperationException) → GK0003 Error
    - Migration with `Down()` having two statements (comment is fine, but two real statements) → GK0003 Error
    - `Up()` method body with DropTable → NO diagnostic (only Down() is gated)
    - A `Down()`-shaped method on a type that does NOT inherit Migration (e.g. ModelSnapshot/Designer) → NO diagnostic (Pitfall 7)
  </behavior>
  <action>
    Create `MigrationDownMethodAnalyzer` as a `public sealed class : DiagnosticAnalyzer` with `[DiagnosticAnalyzer(LanguageNames.CSharp)]`, `public const string DiagnosticId = "GK0003"`, category `GameKit.Security` (match GK0001/GK0002), `DiagnosticSeverity.Error`, `isEnabledByDefault: true`. Title/message: the Down() method must contain only `throw new NotSupportedException(...)`; destructive rollback is disabled (point operators to restore-from-backup).

    Register a syntax-node action on `SyntaxKind.MethodDeclaration`. For each method:
    1. Skip unless `Identifier.Text == "Down"` and the parameter list has exactly one parameter whose type is `MigrationBuilder` (match by simple type-name text to avoid needing the symbol; the deeper inheritance check below disambiguates).
    2. Semantic check: resolve the declaring type symbol and verify it inherits (transitively) from `Microsoft.EntityFrameworkCore.Migrations.Migration`. If it does not (e.g. a ModelSnapshot, a Designer partial, or an unrelated class), return without diagnostic. This is the Pitfall-7 guard — do it via the SemanticModel, walking `BaseType` until `Migration` or null.
    3. Inspect the method body statements (ignore an expression-bodied form — Down() is always block-bodied here; if expression-bodied, treat as non-conforming). The body conforms iff it has exactly ONE statement, that statement is a `ThrowStatementSyntax`, and its thrown expression is an `ObjectCreationExpressionSyntax` whose type name (last identifier) is `NotSupportedException`. Comments/trivia are not statements and are allowed. ZERO statements (empty body) is non-conforming (Pitfall 4). Any other shape → emit GK0003 at the method identifier location.

    Stay within netstandard2.0 + EnforceExtendedAnalyzerRules (no System.IO, no file reads — this is pure syntax/semantic analysis). Add the GK0003 row to AnalyzerReleases.Unshipped.md under "### New Rules" (id | category | severity | notes), matching the existing GK0001/GK0002 row format.

    Do NOT place any literal that the analyzer or its tests negative-grep for inside this plan's prose beyond what is already here; the analyzer matches on AST node types, not on string contents of files.
  </action>
