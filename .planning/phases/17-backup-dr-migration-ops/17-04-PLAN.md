<objective>
Add the `gamekit db` CLI branch with `backup` and `restore` sub-commands (DR-06). `db backup` wraps `pg_dump` (and issues a Redis `BGSAVE`); `db restore` wraps `pg_restore`. Both take an operator-supplied destination — no managed or library-controlled storage path.

Purpose: Give operators a convenience wrapper over the standard, self-hosted Postgres tools so backup/restore is one command, while honoring the GPL/self-hosted/no-cloud constraint (pg_dump/pg_restore are stock Postgres tools; Redis uses BGSAVE).

Output: a `db` branch + 2 commands + 1 path validator + a backup-command test. Binaries are expected on PATH (documented prerequisite), never bundled.
</objective>

  <action>
    Create `BackupPathValidator` (static) exposing `IsSafeAbsolutePath(string path) -> bool`: returns true only when the path is rooted/absolute and contains no `..` segment (reject relative paths and any traversal). Commands call this and exit with code 2 + a clear message when it returns false, BEFORE starting any process.

    Create `DbBackupCommand : AsyncCommand<Settings>` in namespace `GameKit.Cli.Commands.Db`. Settings: `--connection-string` (Postgres; same env fallback chain as MigrateCommand), `--output <PATH>` (required; validated by BackupPathValidator), and optional `--redis-connection <CONN>` to additionally trigger a Redis snapshot.

    Postgres backup: parse the connection string with `NpgsqlConnectionStringBuilder` to extract Host/Port/Database/Username/Password. Build a `ProcessStartInfo { FileName = "pg_dump", UseShellExecute = false, RedirectStandardError = true }` with arguments `--host=... --port=... --username=... --format=custom --file=<output> <database>`. Set `psi.Environment["PGPASSWORD"] = password` (NEVER pass the password as a CLI arg — Info Disclosure mitigation). Start, `await WaitForExitAsync()`, and on non-zero exit print stderr and return that code. Document in the command description + help that `pg_dump` must be on the operator's PATH (not bundled).

    Redis backup (when `--redis-connection` supplied): connect via `StackExchange.Redis` `ConnectionMultiplexer.ConnectAsync`, get the server, and call the background-save API (`IServer.SaveAsync(SaveType.BackgroundSave)` / `BackgroundSaveAsync` — confirm the exact StackExchange.Redis 2.8.41 method name against the package). Report to the operator that BGSAVE was issued and that they must copy the RDB file from the Redis data directory (restore is a documented filesystem-copy procedure, not a CLI wrapper — per 17-RESEARCH Architectural Responsibility Map).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI flags → spawned pg_dump/pg_restore process | untrusted `--output` / `--file` paths and a secret password cross into a child process |
| backup artifact on disk | the dump may contain PII (player rows) — encryption at rest is the operator's responsibility (runbook, Plan 06) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-04-01 | Tampering | `--output` / `--file` path | mitigate | BackupPathValidator rejects non-absolute paths and any `..` segment before any process starts (path-traversal guard) |
| T-17-04-02 | Information Disclosure | Postgres password | mitigate | PGPASSWORD set via ProcessStartInfo.Environment, never as a CLI argument (not visible in `ps`); test asserts it is absent from arguments |
| T-17-04-03 | Tampering | restore target database | mitigate | `db restore` requires an explicit `--database` and prints the resolved host/port/db before running, preventing a silent restore into the wrong DB |
| T-17-04-04 | Information Disclosure | backup artifact contents (PII) | transfer | Encryption-at-rest of the dump is the operator's responsibility — documented in the Postgres backup runbook (Plan 06, DR-01) |
</threat_model>
