<objective>
Stand up the DocFX API-reference gate (DOCS-01): a committed local tool manifest pinning docfx 2.78.5, a repo-root `docfx.json` scoped to `src/**/*.csproj`, the 2-line `Directory.Build.props` fix that unblocks `--warningsAsErrors`, and a CI step that runs the strict gate on every build.

The blocking finding (verified live in research): `docfx metadata --warningsAsErrors` exits 255 on two "Duplicate source file" warnings for `AnalyzerReleases.Shipped.md`/`Unshipped.md` in GameKit.Build. Root cause: `Directory.Build.props` adds these two files via explicit `<AdditionalFiles>` under the `AssemblyName == 'GameKit.Build'` condition, but the Roslyn analyzer SDK ALSO auto-detects them — docfx sees both paths for one physical file. Fix: delete those two explicit `<AdditionalFiles>` lines (the SDK auto-discovery is sufficient; regression risk none). With that fix, `docfx --warningsAsErrors` exits 0 with 0 warnings 0 errors. XML doc coverage is already complete (CS1591 is a warning-as-error repo-wide) — no doc-writing sprint needed here.

Purpose: A CI gate so XML doc coverage and cross-references never silently regress.
Output: `.config/dotnet-tools.json`, `docfx.json`, `.gitignore` updates, the `Directory.Build.props` fix, and the CI gate step.
</objective>
