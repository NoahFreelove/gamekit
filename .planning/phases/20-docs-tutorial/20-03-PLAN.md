<objective>
Deliver the getting-started tutorial (DOCS-02) and, critically, the CI smoke test that proves the tutorial happy-path actually works end-to-end. This is the highest-risk deliverable in the phase.

The smoke test boots an in-process host with the full GameKit chain against Testcontainers Postgres + Redis, then drives the exact tutorial path: two guest logins → enqueue two tickets with `poolName: null` → poll status until the in-process ticker forms a match → both players accept → assert `GET /health/ready` returns 200.

Architecture decision (verified against the codebase): the established pattern in `tests/GameKit.OpenApi.Integration.Tests/OpenApiTestApp.cs` deliberately hand-builds an in-test host that mirrors `samples/TicTacToeDuel/Program.cs` rather than using `WebApplicationFactory<Program>`, because the sample's Program is internal-by-default and standing up the real sample needs on-disk JWT keys + appsettings. Mirror that proven pattern (ephemeral RSA keypair, per-test fresh database, full Add*+Map* chain, in-process matchmaking ticker). This is more robust than WebApplicationFactory against the sample and matches how every other GameKit integration test boots.

Purpose: An honest, reproducible-offline CI gate that the documented tutorial path forms a match and the app reaches readiness.
Output: A new `tests/GameKit.Tutorial.SmokeTests/` project (added to the solution) and `docs/tutorial/getting-started.md`.
</objective>
