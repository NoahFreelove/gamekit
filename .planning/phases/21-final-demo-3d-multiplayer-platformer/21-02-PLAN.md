## D-09 AMENDMENT (fixed-delta, not margin-scaled) — READ BEFORE IMPLEMENTING

D-09 specifies a rating update "scaled by the time margin (bigger gap → bigger swing)". This sub-clause is **dropped and replaced with a fixed-delta rule**, for a forced reason confirmed by the orchestrator and RESEARCH (Pitfall 5):

`src/GameKit.Rankings/Algorithms/RankingBatch.cs` defines `MatchOutcome(Guid PlayerId, Guid OpponentId, MatchResult Result)` — there is **no Score/margin field**. The completion-time margin is NOT propagated into the rating batch. Carrying it there would require adding a field to a `GameKit.*` package public API, which the SPEC prohibits ("Changes to any GameKit.* package public API") and D-15 reinforces. SPEC (WHAT) outranks CONTEXT D-09 (HOW), so the resolution is forced: implement **fixed-delta Elo** — Win = +K, Loss = −K, Draw = 0, symmetric. This still satisfies R6 (verifiable leaderboard change via a custom rule, `Name != "glicko2"`), D-10 (exact integer-ms tie → draw, symmetric, no asymmetric change), D-11 (batched-only), and D-12 (drives the admin leaderboard). The head-to-head outcome itself (faster integer-ms time = Win) is decided by the GameServer when it posts session-complete with `SessionResult.Win`/`Loss`/`Draw` (21-04) — the time comparison lives there, not in the rating algorithm. **The executor must keep this note in the SUMMARY so the reviewer sees the amendment is intentional, not a silent scope drop.**
</objective>
