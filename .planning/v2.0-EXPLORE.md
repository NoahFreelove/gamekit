# v2.0 Exploration Handoff — Try the New Features

> What shipped in v2.0 and how to actually exercise it. Every API name, route, and option below is the real shipped surface (verified against source 2026-06-07). The **integration tests are the executable documentation** — when in doubt, read the cited test; it shows exact wiring against real Postgres + Redis.

## 0. Stand up the backing services + sample app

```bash
docker compose up -d          # Postgres + Redis (root docker-compose.yml)
dotnet run --project samples/TicTacToeDuel/TicTacToeDuel.csproj
```
- Admin console: `http://localhost:<port>/admin` — dev login **`root` / `uat-dev-2026`** (superadmin). Re-bootstrap instructions in `samples/TicTacToeDuel/.dev-admin.env`.
- `samples/TicTacToeDuel/` is the **composition root** — the `Program.cs` `AddGameKit().Add…()` chain is where you turn features on. Some v2.0 features are opt-in and may need a builder call added there (noted per feature).
- Run the whole proof suite anytime: `dotnet test GameKit.sln` (needs Docker — Testcontainers).

## 1. Argon2 password hashing (opt-in) — AUTH-17/18
**Enable:** add `.UseArgon2()` to the GameKit builder chain (replaces the default BCrypt `IPasswordHasher`).
**Try it:** register/login a password user — new hashes are `$argon2id$…`. Existing BCrypt users are **transparently rehashed to Argon2 on their next successful login** (no forced reset).
- Package: `GameKit.Auth.Argon2` · Knob: `AllowInsecureParametersForTesting` (Development-only, guarded — never use in prod).
- Proof: `tests/GameKit.Auth.Integration.Tests/ArgonRehashOnVerifyTests.cs`.

## 2. Google / Apple / Epic OAuth (opt-in) — AUTH-19..22
**Enable:** `.AddGoogle(...)`, `.AddApple(...)`, `.AddEpic(...)` (each its own NuGet package; each registers an `IOAuthProvider`, identity-linked under the `(provider, external_id)` uniqueness contract).
**Try it:** the standard auth callback flow per provider; new identities land as ordinary `player_identities` rows.
- Packages: `GameKit.Auth.Google` / `.Apple` / `.Epic`. (Steam + Discord from v1 still work.)

## 3. Rating-aware matchmaking — MATCH-16/17 + RANK-17
**Enable:** on the Rankings builder, `.WithRatingsFrom<RankingsRatingSource>()` (default stays the Core null-object = rating 0, so matchmaking has no hard Rankings dependency).
**What changes:** `MatchmakingService.EnqueueAsync` now reads each player's real Glicko-2 rating into the Redis ticket hash; `EloRange` brackets on real skill. Guardrails ship with it — per-ladder `MaxBracketWidth` + `MinPoolDepthBeforeBracketExpansion` (set on `MatchmakingLadderConfig` via `AddLadder`).
- Proof: `tests/GameKit.Matchmaking.Integration.Tests/RatingAwareEnqueueTests.cs`, `…/Strategy/EloRangeGuardrailTests.cs`.

## 4. Rank decay + placement matches — RANK-15/16
**Decay:** a leader-elected `BackgroundService` inflates RD (not points) for inactive players; wired automatically by `AddRankings()` (`AddDecayInfrastructure`). Tunable via the rankings decay options.
**Placement:** new players run N placement games (`PlacementMatchCount`); their rating/RD show as **null** on the leaderboard until placement completes (`PlacementMatchesRemaining` counts down atomically).
- Proof: `tests/GameKit.Rankings.Integration.Tests/RankDecayTests.cs`, `PlacementMatchTests.cs`.

## 5. Regional pools + backfill — MATCH-18/19
**Regional:** `AddLadder("ranked", c => c.AllowedRegions = new[] { "us-east", "eu-west" })`. Enqueue with a `RegionName` → routes to Redis key `mm:queue:{ladderId}:{regionName}`; `null` → the `"default"` pool (v1-compatible). A region not in `AllowedRegions` → **HTTP 400**. The ticker auto-scans `default` + every allowed region (no ticker code change).
**Backfill:** `POST /api/matchmaking/backfill` creates a `Backfill`-typed ticket at Redis score 0 → processed ahead of normal tickets. Under-participating backfill players get **no rating change** (guard reads `MinParticipationFractionForRating` from the Rankings ladder JSONB config).
- Proof: `tests/GameKit.Matchmaking.Integration.Tests/RegionalPoolTests.cs`, `BackfillTests.cs`, `BackfillParticipationTests.cs`.

## 6. Account merge (superadmin, high-risk) — AUTH-23..26
**Try it:** `POST /admin/api/players/merge` (requires the `gamekit.admin.superadmin` policy + antiforgery). Irreversibly merges a source `player_id` into a target via a SERIALIZABLE, **crash-resumable** transaction (`account_merges` state machine `pending → committed → redis_cleaned`); re-points all FK references, sums W/L/D keeping the higher-rated rank per ladder, revokes source tokens, tombstones the source (`merged_into_player_id`), and writes a before/after `admin_audit_log` row. The response never includes the source id.
- ⚠️ Known backlog gap (audit W-2): the merge does **not** yet re-point `lobby_members` (Lobby shipped after merge; source is soft-deleted so no crash). Don't merge a player who's in an active lobby until that's closed.
- Proof: `tests/GameKit.Auth.AccountMerge.Integration.Tests/` (27 tests, incl. crash-resume).

## 7. GameKit.Lobby (new package) — LOBBY-01..06 + OPS-11
**Enable:** `.AddLobby(...)` + `app.MapLobby()`. **Requires a registered `IConnectionMultiplexer` (Redis)** — LOBBY-06 mandates the Redis backplane (no Azure SignalR). (Backlog W-1: the "Redis required" error message is terse — register Redis first.)
**Try it:** connect a SignalR client to **`/hubs/lobby`** with a player JWT passed as the `access_token` **query-string** param (unauthenticated upgrade → 401 before handshake). Create/join a lobby, mark ready; when all members are ready the lobby submits a party ticket to matchmaking (via `IPartyService` + `EnqueueAsync`) and transitions `ReadyChecking → InGame`. In-lobby chat is relayed to the SignalR group and **never persisted** (no chat table — LOBBY-04 anti-feature).
- New advisory lock key: `12178347` (pairwise-distinct from the other 5).
- Proof: `tests/GameKit.Lobby.Integration.Tests/` (HubAuthTests, ReadyCheckTests, ChatEphemeralityTests, BackplaneTests, JoinEndpointTests).

## 8. Admin multi-replica + the fixed Rank-adjust page — ADMIN-13/14/15, DIST-07
- **Rank-adjust (try now in the sample):** Admin console → **`/admin/rankings/adjust`** — the dead stub is replaced with a working player-search → adjust-dialog flow that calls `IRankAdjustService` and writes an `admin_audit_log` row.
- **Cross-replica error counter:** when Redis is present, the health panel's error rate aggregates across replicas (`RedisErrorRateCounter`, `gamekit:admin:errors:{bucket}`). Single-instance installs are unchanged.
- **Admin live-event hub:** `AdminEventHub` at `{MountPath}/hubs/events` on the Redis backplane (channel `gamekit:admin:events`), gated by the **`GameKitAdmin` cookie scheme** (a player JWT cannot connect).
- **Multi-replica deployment:** read **`docs/ops/multi-replica.md`** (Data Protection key-ring sharing + Redis backplane / sticky sessions; Redis-only, never Azure SignalR).
- **Release train:** all 5 new packages are on the coordinated MinVer train (same version, exact-pinned siblings, version-assertion covers them). Coherence test: `tests/GameKit.Distribution.Integration.Tests` (`AllTwelveGameKitPackages`).
