# Air-gapped deployment

GameKit's core constraint is **zero cloud-service dependencies** (see `CLAUDE.md`).
That same constraint makes air-gapped deployment first-class: every dependency is
a NuGet package, a `postgres:17.9` image, a `redis:8.6.2` image, and an RSA key
generated by `openssl`. None of those phone home and none of them require the
public internet at runtime.

This doc shows how to stand up a complete GameKit deployment on a network with
no internet egress.

---

## What "air-gapped" rules out

GameKit's runtime path includes no calls to:

- Cloud SaaS APIs (no AWS / Azure / GCP service clients)
- AI / LLM endpoints
- Telemetry endpoints
- License-check endpoints

What it **does** include calls to (and which you must mirror locally):

| Service                       | What hits it                                                | Required? |
|-------------------------------|-------------------------------------------------------------|-----------|
| **Postgres 17.9**             | Every GameKit package that persists                          | Yes        |
| **Redis 8.6.2**               | Matchmaking + Presence                                       | Yes        |
| **Steam OpenID**              | `GameKit.Auth` Steam provider — `https://steamcommunity.com/openid/login` | Only if `--enable-steam` |
| **Discord OAuth**             | `GameKit.Auth` Discord provider — `https://discord.com/api/oauth2/*` | Only if `--enable-discord` |
| **NTP server**                | JWT `exp` validation needs accurate clock — every JWT-bearer endpoint | Yes (use internal NTP)   |

Steam + Discord are the only outbound HTTPS calls in the entire GameKit codebase.
In a true air-gapped environment, both are unreachable, so OAuth-based login is
not available — switch to **Guest + Password providers only** (see "Auth in an
air-gapped environment" below).

## Step 1: NuGet offline feed

Your build host needs every NuGet package GameKit and its transitive dependencies
require. The simplest approach is to mirror the NuGet packages onto an internal
file share or a `Sleet` / `BaGet` / `JFrog Artifactory` server.

### Option A: pre-restore on a network-connected build host, then transfer

```bash
# On a machine WITH internet access, in a checkout of your GameKit-consuming app:
dotnet restore src/MyGame/MyGame.csproj --packages /tmp/nuget-offline

# /tmp/nuget-offline now contains the full transitive closure for your app +
# all GameKit packages. Tar it up and move to the air-gapped network:
tar czf nuget-offline.tar.gz -C /tmp nuget-offline

# Copy across the air-gap boundary (USB, file diode, internal SFTP, etc.).
```

On the air-gapped build host, restore from the offline cache:

```bash
mkdir -p /srv/nuget-offline
tar xzf nuget-offline.tar.gz -C /srv

# Tell dotnet restore to use the offline cache exclusively.
cat > /etc/dotnet/NuGet.config <<'EOF'
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />
    <add key="offline" value="/srv/nuget-offline" />
  </packageSources>
  <fallbackPackageFolders>
    <clear />
  </fallbackPackageFolders>
</configuration>
EOF

# Now restore works without internet:
dotnet restore src/MyGame/MyGame.csproj --source /srv/nuget-offline
```

### Option B: internal NuGet server

Stand up `BaGet` (open-source, self-hostable; not a GameKit dependency, just a
recommendation) on an air-gapped host, push the same offline cache to it once,
then point every consumer at the internal URL:

```xml
<!-- NuGet.config in your app repo -->
<configuration>
  <packageSources>
    <clear />
    <add key="internal" value="https://nuget.internal/v3/index.json" />
  </packageSources>
</configuration>
```

Option B scales better across multiple teams; Option A is the simplest single-deploy
path.

### Refresh cadence

NuGet packages are pinned in `Directory.Packages.props` (CPM). You only need to
refresh the offline cache when:

- You upgrade GameKit (new version of `GameKit.Core` / `GameKit.Auth` / etc.).
- You add a new transitive dependency in your own code.
- A security advisory recommends a patch-level bump on a transitive package.

Pin-by-pin upgrades are the only path — never `dotnet add package` without
recording the new pin and re-mirroring.

## Step 2: container images (if you use Docker)

Mirror the two images GameKit's stack uses into your internal registry:

```bash
# On a network-connected host:
docker pull postgres:17.9
docker pull redis:8.6.2

docker save postgres:17.9 redis:8.6.2 -o gamekit-base-images.tar
# Transfer gamekit-base-images.tar across the air-gap.
```

On the air-gapped host:

```bash
docker load -i gamekit-base-images.tar

# (Optional) re-tag for your internal registry.
docker tag postgres:17.9 registry.internal/postgres:17.9
docker tag redis:8.6.2 registry.internal/redis:8.6.2
docker push registry.internal/postgres:17.9
docker push registry.internal/redis:8.6.2
```

Update your `docker-compose.yml` to pull from the internal registry:

```yaml
services:
  postgres:
    image: registry.internal/postgres:17.9
    # ... rest as shipped
  redis:
    image: registry.internal/redis:8.6.2
    # ...
```

The shipped `docker-compose.yml` references `postgres:17.9` and `redis:8.6.2` as
upstream tags by default. Replacing those two lines is the only change required
for an air-gapped Docker deployment.

If you prefer the bare-metal install path, follow [`bare-metal.md`](bare-metal.md)
— you only need apt mirrors of `pgdg` and `packages.redis.io`, both of which are
straightforward to mirror with `apt-mirror` or `aptly`.

## Step 3: JWT key generation on a non-network host

The shipped `scripts/gen-test-rsa-pem.sh` already uses only local OpenSSL — no
network calls. Generate production keys on the air-gapped machine that will run
the app:

```bash
mkdir -p /srv/mygame/keys
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
    -out /srv/mygame/keys/jwt-priv.pem
openssl rsa -in /srv/mygame/keys/jwt-priv.pem -pubout -out /srv/mygame/keys/jwt-pub.pem
chmod 0600 /srv/mygame/keys/jwt-priv.pem
chmod 0644 /srv/mygame/keys/jwt-pub.pem
chown mygame:mygame /srv/mygame/keys/*
```

See [`jwt-keys.md`](jwt-keys.md) for rotation procedures (which also do not
require internet — only `openssl` + a copy of the running service's config).

## Auth in an air-gapped environment

Steam + Discord are public-internet identity providers. In an air-gapped
deployment they are unreachable, so the corresponding `GameKit.Auth` providers
**will fail at runtime** if registered. Two clean configurations:

### Configuration A — Guest + Password only (recommended for air-gapped)

```csharp
// Program.cs
services.AddGameKit(opts =>
{
    opts.ConnectionString = builder.Configuration.GetConnectionString("GameKit")!;
})
.AddAuth(authOpts =>
{
    authOpts.Jwt.SigningKeyPath    = "/srv/mygame/keys/jwt-priv.pem";
    authOpts.Jwt.ValidationKeyPath = "/srv/mygame/keys/jwt-pub.pem";
    authOpts.Jwt.Kid               = "prod-2026-05-25";
    // Note: NO authOpts.Steam   = ...  block
    // Note: NO authOpts.Discord = ...  block
});
```

Players authenticate via:

- `POST /auth/login/guest` — anonymous JWT, persists across sessions
- `POST /auth/register` + `POST /auth/login/password` — username + password
- `POST /auth/refresh` — refresh-token rotation

No outbound HTTPS calls; works fully air-gapped.

### Configuration B — Steam / Discord temporarily registered but disabled

If your roadmap includes a future "occasional internet uplink" mode (e.g. a
training facility that goes online once a month for syncs), you can register
the providers and gate them via a feature flag:

```csharp
if (builder.Configuration.GetValue<bool>("Features:EnableSteamLogin"))
{
    authOpts.Steam = new SteamOptions { Realm = "https://mygame.internal/auth" };
}
```

`/auth/challenge/steam` will 404 when the flag is off — visible enough to debug
but invisible enough not to surface in the public API.

## Time sync (NTP)

JWT validation depends on a correct clock — a host whose clock has drifted more
than `ClockSkew` seconds (default 5 minutes in ASP.NET Core's JWT bearer) will
reject every valid token as expired. Air-gapped does not mean "no NTP"; it
means "internal NTP server":

```bash
# Install chrony (most distros).
sudo apt-get install -y chrony

# /etc/chrony/chrony.conf — point at internal NTP servers.
server ntp1.internal iburst
server ntp2.internal iburst

sudo systemctl restart chrony
chronyc tracking
```

If your facility has a GPS or PTP grandmaster, point chrony at it. **Do not** ship
without time sync — the failure mode is "every login looks expired", which is hard
to diagnose without thinking to check the clock.

## Air-gapped operational checks

```bash
# 1. No outbound DNS during normal operation. After bringing the app up:
sudo iftop -i eth0 -P                     # watch for unexpected outbound
# Or static check:
sudo netstat -tnp | grep ESTABLISHED       # every connection should be to your internal subnet

# 2. Postgres + Redis healthy + reachable (same as bare-metal.md).
sudo -u mygame psql -h 10.0.0.5 -U gamekit_app -d gamekit -c "SELECT 1;"
redis-cli -h 10.0.0.5 -a "$REDIS_PASSWORD" ping

# 3. Issue a guest JWT to confirm the auth-without-Steam path works.
curl -sf -X POST https://mygame.internal/auth/login/guest | jq

# 4. The 'gamekit' CLI works without the internet.
dotnet tool install --global GameKit.Cli --add-source /srv/nuget-offline
gamekit migrate -c "Host=10.0.0.5;Database=gamekit;Username=gamekit_owner;Password=$OWNER_PW"
```

## Common mistakes to avoid

- **Restoring against `nuget.org` "just this once".** A single `dotnet restore`
  with an unfiltered NuGet.config pulls hundreds of packages from the public
  internet. Always set `<clear />` in `<packageSources>` before adding your
  internal feed.
- **Pulling `:latest` Docker tags during deploy.** `:latest` requires a registry
  lookup on every pull. Use pinned tags (`postgres:17.9`, `redis:8.6.2`) and
  set `imagePullPolicy: IfNotPresent` (Kubernetes) or rely on the local image
  cache (Docker).
- **Registering Steam/Discord providers without an outbound path.** The OAuth
  handshake calls `https://steamcommunity.com/openid/login` (Steam) and
  `https://discord.com/api/oauth2/token` (Discord). Both block forever in an
  air-gapped network — the `/auth/challenge/*` endpoint times out after 30s.
  Disable the providers or stub them out.
- **Skipping the NTP step.** Clock drift > 5 minutes makes every JWT look
  expired. Some hypervisors (looking at you, VMware) suspend-then-restore VMs
  with a leap-of-hours; chrony catches up but not before traffic fails.
- **Forgetting symbols/PDB.** GameKit ships SourceLink-enabled `.snupkg` files.
  Mirror those alongside the `.nupkg` files so production crash dumps map back
  to source lines.
