# GameKit.SampleGame

Generated by `dotnet new gamekit -n <name>` from the **GameKit.Templates** NuGet
template package. This project is a self-hosted game backend built on
[GameKit](https://github.com/OWNER/gamekit) — a GPL-licensed, .NET-native
backend library for auth, player management, matchmaking, rankings, presence,
and session tracking.

## Topology

This template ships a **two-tier production-style topology**:

| Tier              | Project                                  | Postgres role     | Responsibility                                                                  |
|-------------------|------------------------------------------|-------------------|----------------------------------------------------------------------------------|
| Web tier          | `src/GameKit.SampleGame/`                | `gamekit_owner`   | HTTP API, auth, matchmaking, admin UI; OWNS the database (migrations + writes). |
| Game-server tier  | `src/GameKit.SampleGame.GameServer/`     | `gamekit_reader`  | Reads matchmaking/player state; calls back into the web tier via HTTP.          |

The two projects are **independent processes** at runtime — the game-server has
no `ProjectReference` or `PackageReference` to any `GameKit.*` runtime package
because real game servers usually run on different hosts (sometimes in a
different language) and talk to the web tier purely over HTTP + Postgres.

## Prerequisites

- .NET 10 SDK (10.0.106 or later)
- Docker (for the local Postgres + Redis stack defined in `docker-compose.yml`)
- OpenSSL (for the dev RSA keypair — generated by the template post-action or
  manually via `./scripts/gen-test-rsa-pem.sh`)

## Run

```bash
# 1. Generate a throwaway RSA key pair for local JWT signing/validation.
#    The template post-action already attempts this; re-run it if you got the
#    "post-action failed" warning during template instantiation (Windows
#    without WSL needs the manual run).
./scripts/gen-test-rsa-pem.sh

# 2. Start Postgres + Redis.
docker compose up -d

# 3. Run the web tier (port 5000 by default).
dotnet run --project src/GameKit.SampleGame
# then open http://localhost:5000

# 4. (Optional, in a second terminal) Run the game-server tier.
dotnet run --project src/GameKit.SampleGame.GameServer
```

## Opt-out flags

The template accepts four boolean opt-out flags at generation time. Each omits
the corresponding GameKit package's `PackageReference` and the
`builder.Services.Add<Pkg>()` + `app.Map<Pkg>()` calls from `Program.cs`:

| Flag                  | Omits                                                         |
|-----------------------|---------------------------------------------------------------|
| `--skip-auth`         | `GameKit.Auth` (JWT issuance, Steam/Discord OAuth, password)  |
| `--skip-rankings`     | `GameKit.Rankings` (Glicko-2, session-complete pipeline)      |
| `--skip-matchmaking`  | `GameKit.Matchmaking` (parties + queue + proposal flow)       |
| `--skip-presence`     | `GameKit.Presence` (Redis-TTL heartbeat + in-match panel)     |

`GameKit.Core`, `GameKit.OpenApi`, and `GameKit.Admin.UI` are always included
— Core is required, and the OpenAPI + Admin UI surfaces are always-on
conveniences for the SampleGame topology.

Example:

```bash
dotnet new gamekit -n MyMinimalGame --skip-rankings --skip-matchmaking --skip-presence
```

## Postgres role separation

The repo ships `docker/postgres/init/01-roles.sql` (mirroring upstream GameKit)
which creates three roles:

- `gamekit_owner` — DDL + DML, used by the web tier for migrations + writes.
- `gamekit_app` — DML only on the GameKit schema (intended for a horizontally
  scaled web tier where you do NOT want migrations to run from the app role).
- `gamekit_reader` — SELECT only, used by the game-server tier.

`gamekit_reader` is **denied INSERT / UPDATE / DELETE** by Postgres default
privileges — the role barrier is enforced by the database, not by convention.
The upstream GameKit `DIST-02` integration test asserts this empirically.

In production, rotate all three passwords by following the
`docs/ops/postgres-roles.md` runbook in the GameKit repo.

## Production notes

- The dev RSA keypair under `src/GameKit.SampleGame/keys/` is for **local
  development only**. Rotate before any production deployment (see
  `docs/ops/jwt-keys.md` in the GameKit repo).
- The dev Postgres / Redis container passwords in `appsettings.Development.json`
  and `docker-compose.yml` are well-known. Rotate them before production.
- The Discord OAuth client ID/secret placeholders skip Discord scheme
  registration at startup — replace them in `appsettings.json` once you've
  created a Discord application.
